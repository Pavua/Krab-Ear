# purge_coverage_allowlist.txt — INTENTIONAL survivors of privacy-purge (W1768)
#
# One store id per line (filename, "subdir/", or "prefix_*.ext" glob family).
# A trailing "# reason" comment is required for every entry.  Anything NOT
# listed here that the discovery scanner finds and that handle_purge_all_data
# does not wipe is reported as a GAP by scripts/audit_purge_coverage.py.
#
# Policy (be conservative): only list stores that are demonstrably NOT user PII
# / transcription-derived content — app configuration, compliance trail, model
# caches, security keys whose deletion would corrupt the audit log, and ID-only
# resurrection registries.  When in doubt, leave it OFF this list so the guard
# treats it as a GAP (the safe direction).

# --- App configuration (no transcription content) -------------------------
settings.json            # app config; the PII field (translation_glossary) IS reset by purge step 15
feature_flags.json       # runtime experimental on/off flags — no user content
config_presets.json      # built-in + custom settings presets — no transcription content

# --- W1770: text-processing / paste preferences (user app config, not transcript content) ---
# These persist user *rules and preferences* for how transcripts are processed/pasted.
# They contain no transcript text and no transcript-derived names; like settings.json,
# they are app configuration that should survive a "purge transcription data" wipe.
abbreviations.json          # W1770: user abbreviation → expansion rules (text-processing prefs); no transcript content
text_snippets.json          # voice-triggered text snippet expansions — user-authored config pairs (trigger phrase → expansion text), not transcript-derived content; analogous to abbreviations.json
phonetic_vocab.json         # user phonetic correction vocabulary — user-authored many-to-one variant→canonical pairs (e.g. "пашел"→"Павел"); no transcript content, analogous to abbreviations.json
hallucination_patterns.json # W1770: user-defined regex hallucination filters (text-processing prefs); no transcript content
normalization_profiles.json # W1770: named text-normalization profiles (clean/formal/telegram/...); app config, no transcript content
paste_formatters.json       # W1770: custom paste-format rules per target app; app config, no transcript content
paste_app_memory.json       # W1770: bundle_id → paste-profile preference map; LOW behavioral fingerprint (app names + last-used timestamps). No transcript text. Intentionally retained as app config; purge removes transcript data not UI preferences.
summary_profiles.json       # W1770: LLM summarization style profiles (prompt/format prefs); app config, no transcript content
# W1771 GAP-2: templates.json was WRONGLY allowlisted by W1770 — TemplateManager stores
# free-text `text` with NO filter (email signatures with real names/phones, greetings
# wrapping real names around {name}). That is PII, so it now goes to PURGE via
# TemplateManager.purge_all() (wired in handle_purge_all_data); removed from this list.

# --- W1770: runtime / extensibility artefacts (not user PII) --------------
shutdown_info.json       # W1770: last-shutdown metadata (pid, timestamp, reason) for diagnostics; no user content
plugins/                 # W1770: installed plugin code + plugin.json manifests (extensibility), not transcript data

# --- Compliance / security infrastructure ---------------------------------
privacy_audit.key        # AES key for the compliance audit log (privacy_audit.log is the W957 trail); deleting it would corrupt the audit record. The log itself is home-rooted, not under the configurable data dir, so it is not discovered.
event_bridge_token/      # HMAC bridge-auth секрет между IPC/REST процессами (localhost-only trust boundary); не пользовательские данные, аналог privacy_audit.key. Фактически ОДИН файл (не директория) — сканер помечает его directory-style, т.к. имя ссылается через переменную EVENT_BRIDGE_TOKEN_FILENAME, а не строковый литерал с расширением.
