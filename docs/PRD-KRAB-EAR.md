# PRD: Krab Ear Native

Дата версии: 2026-02-11  
Статус: Active

## 1. Цель

Сделать отдельный от OpenClaw локальный голосовой ассистент для macOS:
- диктовка по одной горячей клавише;
- качественная транскрибация с корректной пунктуацией;
- вставка в активное текстовое поле;
- гарантированное сохранение результата даже при ошибках вставки.

## 2. Основной пользовательский сценарий

1. Пользователь нажимает `Right Option`.
2. Krab Ear запускает запись и подаёт звуковой сигнал старта.
3. Повторное нажатие `Right Option` завершает запись.
4. Локальный backend выполняет STT.
5. Текст добавляется в историю и пытается вставиться в активное поле.
6. Если вставка не удалась, текст остаётся в истории и буфере обмена, а агент показывает панель.

## 3. Функциональные требования (MUST)

- Нативный hotkey в фоне без активного окна.
- Режимы `headless` и `menubar`.
- Локальный offline STT по умолчанию.
- Автовставка текста после транскрибации.
- Безлимитная история транскрибаций.
- Поиск/пагинация/удаление истории в панели управления.
- One-click запуск через `.command`.
- Автозапуск через launchd (опционально).

## 4. Хранилище и контракты

### 4.1 settings.json

Обязательные поля:

```json
{
  "history_policy": "unlimited",
  "history_page_size": 50
}
```

### 4.2 История

Формат: append-only NDJSON  
Файл: `history.ndjson`

```json
{"id":"uuid","ts":"2026-02-11T17:12:33","text":"...","paste_status":"ok|failed"}
```

Удаление: tombstone-журнал `history_tombstones.ndjson`  
Обновление `paste_status`: `history_status.ndjson`

### 4.3 IPC API

- `get_history_page` -> `{"items":[...],"next_cursor":"...|null"}`
- `search_history` -> `{"items":[...],"next_cursor":"...|null"}`
- `delete_history_item` -> `ok/error`

## 5. Нефункциональные требования

- Платформа: macOS (Apple Silicon приоритет).
- Приватность: аудио/текст не отправляются наружу в дефолтном режиме.
- Стабильность: без крэшей в длинных сессиях и soak-тестах.
- UX: первый экран истории открывается быстро, догрузка страниц без фризов.

## 6. Acceptance Criteria

1. История не обрезается при 5/50/200+ записях.
2. После 10 000 записей панель открывает первый экран <= 500 мс.
3. После рестарта приложения история полностью сохраняется.
4. При сбое вставки запись остаётся в истории и текст в буфере обмена.
5. Сценарий `start -> stop -> transcribe -> paste/history` стабилен в повторных циклах.
