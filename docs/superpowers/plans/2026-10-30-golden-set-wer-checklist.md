## (а) Как записать Golden Set — одна кнопка

**Инструмент:** двойной клик по **`Record Golden Set.command`** (корень репо) — он вызывает
`python3 scripts/record_golden.py` (чистый stdlib + ffmpeg, venv не нужен).

Что происходит:
1. Скрипт читает 50 фраз из `docs/golden/r2-scenario.md`: **RU=30, ES=12, EN=8**.
2. По одной фразе за раз: показывает текст → **Enter — начать запись → говоришь → Enter — стоп**.
   Каждая фраза пишется отдельным WAV (16 kHz, mono, PCM16 — канон пайплайна) через
   ffmpeg/avfoundation. Файл пишется в `.part` и переименовывается только после чистого стопа.
3. **Resume:** повторный запуск продолжает с первой незаписанной фразы. Ctrl+C — выйти,
   прогресс сохраняется. Можно писать в несколько сидок.
4. Полезные флаги (проверены по коду):
   - `python3 scripts/record_golden.py --list` — показать все 50 фраз;
   - `--dry-run` — сколько фраз и куда, без микрофона (проверено: 50 фраз, на диске 0);
   - `--device :1` — если микрофон не `:0` (список: `ffmpeg -f avfoundation -list_devices true -i ""`);
   - `--force` — перезаписать всё.

Как говорить (из сценария, это важно для переносимости цифр):
- **свой обычный темп, не по слогам**; пауза ~1 с до и после фразы;
- тот же микрофон и та же комната, что для живой диктовки (чужой голос/синтетика забанены —
  цифры не переносимы);
- тишина/шум — «как в жизни», специально идеализировать не надо;
- первый запуск: macOS спросит доступ Терминала к микрофону — разрешить;
- ориентировочно 30–40 минут на всё (`docs/golden/r2-scenario.md`).

**Приоритет для W4/F1:** блок **RU 1–30** — именно на нём оценивается эффект лексики
(hotwords 43 / phonetic 11/31 — RU-ориентированные). ES/EN — по остатку сил, можно вторым сидом.

### Две команды, которые работают уже сегодня

**1. Транскрибирование golden-файла — существующий прод-путь (REST, процесс :5005):**

```bash
curl -s -X POST http://127.0.0.1:5005/v1/stt/transcribe \
  -F "file=@$HOME/Library/Application Support/KrabEar/golden/ru_001.wav" \
  -F "lang_hint=ru" -F "diarize=false" -F "persist_history=false"
```

Контракт проверен по `KrabEar/backend/rest_server.py` (route `/v1/stt/transcribe`):
ответ `{status, text, confidence, duration_ms, engine, model, language, …}`;
`diarize=false` режет латентность; `persist_history=false` — не засорять историю;
rate-limit 60/мин — 50 файлов проходят. Условия: REST-сервер жив, privacy_mode OFF
(иначе 403 `skipped: privacy_mode`), auth по умолчанию выключен (Mode 3 pass-through).

**2. Сравнение гипотезы с эталоном — харнесса НЕТ, нужно написать (оценка S):**

Малый скрипт `scripts/wer_golden.py`: обходит `~/Library/Application Support/KrabEar/golden/*.wav`,
шлёт каждый в REST (как выше), эталон берёт из `docs/golden/r2-scenario.md` (парсер уже есть в
`scripts/record_golden.py::parse_scenario`), считает WER (Levenshtein по словам — готовая
реализация `compute_wer`/`compute_cer` в `scripts/stt_engine_bench.py`, jiwer не обязателен),
печатает per-фразу и средний WER по языкам. Опционально — сравнение двух прогонов (до/после).

**Харнесс WER-сравнения отсутствует — нужно написать, оценка S** (один файл, ~100 строк,
готовые куски: парсер сценария + compute_wer + REST-вызов).

## (г) Критерии готовности (для владельца)

- [ ] Golden Set записан: `--dry-run` показывает **«Уже записано на диске: 50»** (минимум для W4/F1 — RU=30).
- [ ] Харнесс `wer_golden.py` написан и прогнан на записанном наборе: отчёт per-фраза + средний WER (RU/ES/EN).
- [ ] **Замер «после» (текущий прод с лексикой W4/F1):** средний WER на RU-30 ≤ **10%** —
      рабочий ориентир для обычных фраз (медико-юридические 11–20 могут быть выше — считать отдельно).
- [ ] **Замер «до» (без лексики):** второй прогон с временно выключенной лексикой
      (`set_settings` IPC: hotwords/phonetic-флаги OFF на время прогона, потом вернуть) —
      это отдельное решение владельца (меняет настройки прод; делается осознанно, не сейчас).
      Эффект W4/F1 = WER(до) − WER(после) на одних и тех же WAV.
- [ ] Контрольные фразы: RU 4/5/30 (`могу/сможем`) и EN 5–6 (`maybe`) — сверить отдельно
      (ловушка `maby`, решение по ней ждёт этих эталонов).

## Что НЕ делать

- Не коммитить WAV или отчёты с текстами записей (audio/тексты — только локально).
- Не рестартовать бэкенд ради анализа (REST :5005 уже жив; если нет — координатору, не руками).
- Не включать/выключать лексику без явного решения (замер «до» = изменение настроек прода).
