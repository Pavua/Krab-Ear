# W6 — гард против мёртвых Swift-методов

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:test-driven-development. Шаги — чекбоксы (`- [ ]`).

**Goal:** `scripts/audit_dead_swift_methods.py` — CI-гард, находящий объявленные, но нигде не вызываемые Swift-методы агента. Python-сторона уже закрыта пятью аудиторами (orphan imports, decorative wiring, dead extracted modules, dispatch targets, dead IPC handlers); Swift-половина не покрыта ничем.

**Анти-rebuild (проверено):** `audit_dead_ipc_handlers.py` и `audit_ipc_contract_drift.py` сканируют Swift только как ИСТОЧНИК вызовов IPC-методов Python; ни один не ищет мёртвые методы ВНУТРИ Swift (`grep -c 'func '` по обоим = 0). Файла `audit_dead_swift*` не существует. Двойника не создаём.

**Architecture:** Swift AST в проекте недоступен и тулчейном не выдаётся, поэтому разбор построчно-регексовый — по образцу тех же двух аудиторов (`rglob("*.swift")` → `splitlines()` → `re.compile` на известные формы). Разведка по живому коду (145 файлов, 1841 объявление `func`, 1568 уникальных имён): кандидатов «ноль вызовов» до фильтрации — 95, после правил-исключений — **17**; отдельная категория — 41 метод, вызываемый ТОЛЬКО из `Tests/` (жив для тестов, мёртв в проде).

**🔴 Правила-исключения — главная часть волны.** Наивный критерий «имя не встречается как `name(`» даёт ~78 ложных срабатываний из 95. Обязательны:

1. **Trailing-closure вызов**: `monitor.setWedgeProbe { ... }` — вызов БЕЗ скобок. Искать И `name\s*\(`, И `name\s*\{`. Без этого 12 живых методов попадают в мёртвые.
2. **`override`** — компилятор Swift не даст скомпилировать `override func` без совпадающей сигнатуры супертипа; вызывает фреймворк. Всегда живой.
3. **Соответствие протоколу — ТОЛЬКО с проверкой имени.** Наивное «класс конформит `*Delegate` ⇒ метод живой» ложно почти в половине случаев (18 из 40): так были бы скрыты и реальные находки внутри `AgentAppDelegate`. Нужны ОБА условия: охватывающий тип конформит протоколу с `Delegate`/`DataSource`/`Validation` в имени **И** имя метода совпадает с известным паттерном требований (`tableView…`, `windowDid…`, `audioPlayerDid…`, `validateMenuItem`, …).
4. **Известные lifecycle-имена** AppKit/Foundation (`applicationDidFinishLaunching`, `viewDidLoad`, `mouseEntered`, `loadView`, …) — вызывает рантайм.
5. **`@objc` без `#selector`** — 🔴 НЕ исключение, а высокоприоритетный кандидат: в этом коде динамического `NSSelectorFromString`/`Selector("` нет вообще (grep пуст), и все три такие находки оказались реально непроводными хендлерами.
6. **Bare-reference** (`[...].forEach(relaxHorizontalCompression)`) — имя как отдельное слово без `(` и `{`.
7. **Коллизия одинаковых имён у несвязанных типов** — главный источник ошибок В ОБЕ стороны. `AgentRecoveryLogger.record` реально мёртв, но выглядел живым из-за посторонних `record(...)` в двух тестовых spy-классах. Для коротких/частых имён (`record`, `clear`, `start`, `stop`, `close`, `run`, `handle`) счёта по имени НЕДОСТАТОЧНО — такие имена уводить в отдельную категорию «нужна ручная проверка», а не объявлять мёртвыми.
8. **test-only** — вызовы только из `Tests/**`: отдельная метка, НЕ «мёртвый код».

**Tech Stack:** конвенция соседних аудиторов — `from __future__ import annotations`, докстринг с ROOT CAUSE + Usage + exit-коды, флаги `--fail-on-found` / `--json` / `--selftest`, exit 0 (чисто или report-only) / 1 (находки + `--fail-on-found`) / 2 (сломанное окружение), allowlist-файл `scripts/<name>_allowlist.txt` со строками `тип:значение` и `#`-комментариями.

**База:** `origin/codex/krab-ear-v2`. Worktree: `.claude/worktrees/stoic-haibt-629bc7`, ветка `feat/w6-audit-dead-swift-methods`.

**Баны:** гард стартует в режиме **report-only** (без `--fail-on-found` в CI), пока владелец не подтвердит список находок — иначе первый же прогон покрасит ветку на 17 находках; не удалять найденные методы в этой волне (гард ≠ чистка); не запускать собранный `KrabEarAgent`; `git add` явными путями.

**Вне скоупа:** удаление найденных мёртвых методов (отдельная волна после ревью списка); Swift-тесты; правка самих находок.
