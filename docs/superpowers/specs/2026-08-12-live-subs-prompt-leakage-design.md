# Live-субтитры: утечка инструкции-промпта в распознанный текст

Дата: 2026-08-12. Повод — владелец включил субтитры на русском YouTube-видео
(интервью, 1:49:24) после того, как backpressure-фикс (F3) заставил их
показывать текст. Текст появился, но с мусором: на экране —
«Сохраняй смысл 0 тяги, мастеряй смысл 0 тяги», «ня здесь здесь чёрный тоже /
О Здесь тоже», плюс тост «Whisper зациклился — переговори фразу».

## 1. Корень (доказан, не гипотеза)

`backend.log` в момент теста:

```
14:02:54 WARNING: Whisper repetition loop detected: repeated_bigram x17: смысл и
00:41:54 WARNING: Whisper repetition loop detected: repeated_bigram x17: сохраняй смысл
00:44:55 WARNING: Whisper repetition loop detected: repeated_bigram x40: и т.д.
```

Фразы «сохраняй смысл» в интервью нет и в истории владельца нет (проверено
IPC-запросом по 50 последним записям). Источник найден — `core/config.py:135`:

```python
TRANSCRIBE_PROMPT: str = "Ты транскрибируешь русскую речь. Сохраняй смысл, ставь корректную пунктуацию и заглавные буквы."
```

Это **инструкция**, передаваемая Whisper как `initial_prompt`. Но
`initial_prompt` у Whisper — не поле команд, а **префикс предшествующего
текста**: модель продолжает его стилистически. На малоинформативном или
плотном аудио она начинает выговаривать сам промпт и зацикливаться на нём.

## 2. Почему это именно sibling-gate asymmetry

Тот же баг УЖЕ находили и чинили — но ровно для одного пути. `engine.py:893`:

```python
# Preview path идёт с пустым prompt'ом: короткие аудиобуферы (<3s)
# провоцируют whisper на "leakage" initial_prompt'а в output как
# артефакта. ... Defense-in-depth: _postprocess_preview_text в
# service.py срезает известные фрагменты промпта как safety net.
if is_preview:
    dynamic_prompt = ""
else:
    dynamic_prompt = f"{settings.TRANSCRIBE_PROMPT} Тематика: {domain_desc}"
```

Live-субтитры флашатся каждые **~3 секунды** (`_FLUSH_THRESHOLD_SEC`) — ровно
то условие «короткие аудиобуферы», от которого защищали preview. Но
`LiveSubsService._process_window` зовёт ПОЛНЫЙ путь
(`live_subs_service.py:551`):

```python
stt_result = self._transcriber.transcribe(
    audio, quality_profile="balanced", skip_vad_prefilter=True
)
```

→ получает и инструкцию-промпт, и — через `build_initial_prompt` — **историю
диктовок владельца** и его hotwords как контекст. Для системного звука из
чужого видео всё три источника не просто бесполезны, а вредны: они смещают
распознавание в сторону лексики диктовок владельца.

## 3. Решение

### G1 — live subs транскрибирует без инструкции и без чужого контекста

Новый явный параметр `Transcriber.transcribe(..., context_free: bool = False)`,
пробрасываемый в `AudioEngine.transcribe`. При `context_free=True`
`dynamic_prompt` формируется пустым — тем же способом, что уже делает ветка
`is_preview`, но БЕЗ вранья про «это превью» (у превью своя семантика:
bounded mlx_lock, возврат пустого текста при неудачном захвате — она live
subs не подходит, там нужен обычный путь).

`LiveSubsService._process_window` передаёт `context_free=True`.

🔴 Почему отдельный флаг, а не переиспользование `is_preview`: `is_preview`
уже гейтит ЧЕТЫРЕ разных вещи (пустой промпт, пропуск диаризации, пропуск
loop-детектора, пропуск LLM-passes). Live subs нужна ровно одна из них.
Навесить на `is_preview` — получить три незапрошенных изменения поведения.

### G2 — зацикленное окно не показывается пользователю

Сейчас детектор при срабатывании возвращает текст НЕИЗМЕНЁННЫМ, осознанно:
комментарий `engine.py:1138` — «не врём про input: пользователь видит
реальный вывод Whisper плюс warning-тост и решает, перезаписать ли». Для
ДИКТОВКИ это правильно (человек может перезаписать фразу).

Для live-субтитров — нет: перезаписать чужое видео нельзя, а на экран
попадает «Сохраняй смысл 0 тяги». Окно с обнаруженным loop'ом должно
**дропаться** (механика дропа уже есть после F3), с инкрементом
существующего счётчика и лог-строкой.

Гейт применяется ТОЛЬКО к пути live subs — семантика диктовки не меняется.

## 4. Осознанно НЕ в скоупе

- **Смена самого `TRANSCRIBE_PROMPT` на стилевой образец вместо инструкции.**
  Инструкция-в-initial_prompt — сомнительный приём и для диктовки тоже, но
  трогать его глобально без замера качества нельзя: он стоит там осознанно
  «для пунктуации/брендов/имён», и регресс диктовки владельца дороже, чем
  выигрыш. Кандидат в отдельную волну С ЗАМЕРОМ (A/B на наборе записей).
- **OOM «Не хватило памяти — выгрузи LM Studio»** (тост 14:01): живой
  `vm_stat` в момент разбора — swap 1320 МБ из 2048 МБ занято, память под
  давлением от внешних процессов. Это среда, не код; отдельный вопрос —
  стоит ли live subs вообще держать вторую MLX-модель при активном
  LM Studio. Не решается этой волной.
- Ускорение STT под 2x-темпом — дроп отставших окон остаётся правильной
  реакцией (F3).

## 5. DoD

- G1: при `context_free=True` в `initial_prompt` не попадает ни
  `TRANSCRIBE_PROMPT`, ни история, ни hotwords; при `False` поведение
  побайтово прежнее (тест на обе ветки).
- G1: `LiveSubsService` реально передаёт флаг (source-контракт — класс
  «декоративная проводка»).
- G2: окно с `is_likely_repetition_loop == True` не эмиттит событие,
  инкрементит счётчик, пишет лог; путь диктовки не затронут (тест).
- TDD RED→GREEN на каждый пункт; pytest-кластер + flake8 + ubuntu-parity.
- Живая проверка после мержа: включить субтитры на том же видео, убедиться,
  что в тексте нет фрагментов «сохраняй смысл»/«транскрибируешь» и в логе
  нет новых `repetition loop detected` от live-subs окон.
