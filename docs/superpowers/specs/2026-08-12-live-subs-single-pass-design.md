## 1. Корень (доказан логом, не гипотеза)

Одно окно субтитров длиной **2.5 секунды**, `backend.log` 14:56:13–14:56:23:

```

14:56:13,713  GigaAM-RNNT добавлен в chain первым (lang=ru, engine=gigaam-rnnt)
14:56:14,566  GigaAM транскрибация завершена: len=0 chars, confidence=0.900
14:56:14,566  GigaAM не распознал речь — request-local fallback на Whisper
14:56:17,205  [STT] balanced→whisper-large-v3-mlx retry: confidence 0.61 < 0.65
14:56:19,355  [STT] balanced→whisper-large-v3-turbo retry: confidence 0.61 < 0.65
14:56:23,202  STT готово: 9.49s, уверенность raw=0.61, язык: auto
```

**Три тяжёлых прохода STT на окно в 2.5с, суммарно 9.49с.** Окна приходят
каждые ~3с (`_FLUSH_THRESHOLD_SEC`) → конвейер втрое медленнее реального
времени. Backpressure (F3) исправно дропает отставшие окна, поэтому владелец
видит обрывки, а не текст. Он же объясняет и остальное, что он наблюдал:

- **Утечка промпта.** Повторные проходы Whisper по малоинформативному
  системному звуку — ровно то условие, при котором модель начинает
  выговаривать `initial_prompt` и зацикливаться. Флаг `context_free`
  (волна G1) убирает содержимое промпта, но не убирает лишние проходы.
- **MLX OOM и watchdog timeout 120с.** Три модели (`gigaam` + `large-v3` +
  `large-v3-turbo`) на каждое окно, при живом LM Studio на 36 ГБ.

## 2. Что оказалось НЕВЕРНЫМ в предыдущей спеке

Проверено грепом по всему репозиторию, не только по тестам:

- **`STTRouter.select_model()` не вызывается в проде вообще** — единственные
  вызовы в `KrabEar/tests/test_stt_router.py`. Реальный выбор движка идёт в
  `engine.py:2037` через `_effective_lang`.
- **`AudioLanguageID.detect()` в проде недостижим** — он вызывается только
  из `STTRouter.select_model()`. Заявленной «автодетекции языка на каждом
  окне, гоняющей энкодер mlx-whisper» НЕ БЫЛО. Настройка
  `stt_audio_lang_id_enabled: True` сейчас декоративна.
- **GigaAM для русского выбирался и БЕЗ явного языка**: `_effective_lang`
  падает на `TRANSCRIBE_LANGUAGE` (дефолт `"ru"`), лог подтверждает
  `lang=ru, engine=gigaam-rnnt`.

Поэтому `live_subs_language` (уже смержено) — **не фикс проблемы владельца**,
а самостоятельный enabler: язык субтитров теперь задаётся независимо от
языка диктовки, иначе иностранное видео принудительно шло по RU-цепочке.

## 3. Решение: явный однопроходный режим

Новый параметр `AudioEngine.transcribe(..., single_pass: bool = False)`,
пробрасываемый из `Transcriber.transcribe`. При `single_pass=True`:

1. **Цикл ретраев по уверенности не выполняется** (`engine.py:1613`,
   порог `STT_MIN_CONFIDENCE_THRESHOLD=0.65`) — эффективно `max_retries=0`.
2. **Request-local fallback после первого движка не выполняется**: что первый
   движок вернул, то и результат. Пустой ответ GigaAM = в окне нет речи,
   субтитр не показываем. Это ДЕШЕВЛЕ и ЧЕСТНЕЕ, чем добывать из шума
   низкоуверенный текст.

`LiveSubsService._process_window` передаёт `single_pass=True`.

🔴 **Почему отдельный флаг, а не `is_preview`**: `is_preview` гейтит уже
четыре разные вещи (пустой промпт, пропуск диаризации, пропуск loop-детектора,
пропуск LLM-passes) плюс имеет собственную семантику bounded `mlx_lock` с
возвратом пустоты при неудачном захвате. Live subs нужен обычный путь и
ровно одно изменение. Та же логика, по которой в волне G1 завели
`context_free` вместо переиспользования `is_preview`.

🔴 **Путь диктовки не трогаем.** Для диктовки ретрай по уверенности —
правильное поведение: пользователь ждёт один результат и готов заплатить
секундами за качество. Для живого потока цена — потеря следующих окон.

## 4. Осознанно НЕ в скоупе

- **Почему GigaAM возвращает пусто на системном звуке.** Отдельный вопрос
  (сжатый звук, музыка, наложение голосов, 2x-темп). Однопроходный режим
  делает пустой ответ дешёвым и безвредным независимо от причины.
- **Дребезг профиля**: в логе `Смена профиля STT: balanced -> max` и сразу
  `max -> balanced` в ту же миллисекунду — два переключения подряд, каждое
  потенциально перезагружает MLX-модель. Реальная находка, но отдельная.
- **Мёртвые `STTRouter.select_model` / `AudioLanguageID`** (§2). Целая
  подсистема, упражняемая только собственными юнит-тестами — класс
  «test-validates-the-hole». Отдельная волна: удалять или подключать.
- Смена `TRANSCRIBE_PROMPT` — по-прежнему требует A/B-замера.

## 5. DoD

- `single_pass=True` → ноль ретраев по уверенности и ноль fallback-проходов
  после первого движка (тест считает ФАКТ вызовов движка, а не длительность).
- `single_pass=False` → поведение побайтово прежнее (тест на обе ветки).
- `LiveSubsService` реально передаёт флаг (source-контракт — класс
  «декоративная проводка»).
- Пустой результат первого движка при `single_pass=True` → окно не эмиттит
  событие, путь не падает.
