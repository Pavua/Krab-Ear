# Этап 2 волны телефонии: удаление адаптеров и кнопка в панели

Дата: 2026-09-03. Продолжение `2026-09-03-telephony-consolidation.md`.
Предусловие: этап 1 (#1989) в проде, живая проверка звонка пройдена.

## Что удаляется

| файл | строк |
|---|---:|
| `telnyx_adapter.py` | 451 |
| `twilio_adapter.py` | 490 |
| `sip_local_adapter.py` | — |
| `call_provider_factory.py` — ветки telnyx/twilio/sip_local | часть |
| тесты телефонии | 23 файла |

`call_provider.py` (Protocol) **остаётся** — на нём стоит `GatewayCallProvider`.
`call_session*`, `call_cost_estimator`, `call_silence_probe`, `call_auto_end`
остаются: журнал, оценка стоимости и авто-завершение работают поверх любого
провайдера, а у шлюза свой `max_duration_sec` дублирует лишь часть.

## Порядок

1. Живая проверка `call_start` (loopback или номер владельца) — **до** удаления.
2. Удаление адаптеров + их тестов, чистка веток фабрики, `CALL_PROVIDER` → `gateway`
   единственным значением (плюс `none`).
3. Swift: секция «Автозвонки» перестаёт спрашивать ключ Telnyx и исходящий номер
   (их держит шлюз), получает поле цели звонка и кнопку, зовущую `call_start`.
   Поля `telnyx_api_key` / `telnyx_from_number` уходят из панели.
4. Гейт: `make audit-all`, полный прогон, ubuntu-паритет, Swift-контракты, парити-бинарь.
5. Документация: `IPC_API_REFERENCE.md` (+`call_start`, −удалённые), `CLAUDE.md`
   (граница с Voice Gateway, чтобы дубль не отрос), `NOW.md`.

## Инварианты

- 🔴 Удаление IPC без правки Swift = «метод не найден» в проде. Правки идут одним PR.
- Настройки `telnyx_*` остаются в `DEFAULT_SETTINGS` до отдельного решения: их
  удаление ломает settings.json у владельца при откате. Помечаются как вестигиальные.
- Бэкап: тег `telephony-archive-2026-09-03`, ветка `archive/telephony-2026-09-03`.
