# Live-субтитры: явный язык → GigaAM для русского, Whisper для остального

Дата: 2026-08-12. Идея владельца по итогам живого теста: «для русских
субтитров и проверок на русском можем тоже использовать GigaAM, а не
Whisper, а для иностранной речи уже да».

## 1. Почему идея верна (проверено по коду, не на слух)

**GigaAM структурно не может утечь промптом.** `grep -n "prompt"
core/pipeline/stt_gigaam.py` → **ноль совпадений**: адаптер не принимает
`initial_prompt` вовсе. Класс бага «Whisper выговаривает
`TRANSCRIBE_PROMPT`» (см. `2026-08-12-live-subs-prompt-leakage-design.md`)
для GigaAM невозможен по построению, а не погашен флагом `context_free`.
Флаг остаётся как защита для не-RU пути.

**GigaAM точнее на русском** — собственный бенч проекта (память
`reference_gigaam_vs_whisper_bench`): на mat-heavy RU точнее Whisper,
поэтому и стоит первым в цепочке для RU.

**Сейчас live subs язык НЕ передают.** `_process_window` зовёт
`self._transcriber.transcribe(audio, quality_profile="balanced",
skip_vad_prefilter=True, context_free=True)` — без `lang_hint`. Значит на
КАЖДОМ окне (~3с) отрабатывает автоопределение языка через
`AudioLanguageID` (`stt_audio_lang_id_enabled: True`), которое само гоняет
энкодер mlx-whisper. На сжатом system-audio из YouTube (музыка, наложение
голосов, 2x-темп) детекция промахивается → маршрут уходит на Whisper
multilingual. Живое подтверждение — `MLX watchdog timeout 120.0s
(model=mlx-community/whisper-large-v3-mlx)` в логе инцидента 14:0x.

**Побочный выигрыш — память.** Автодетекция на каждом окне держит
whisper-энкодер горячим параллельно с основной моделью. Инцидент 14:01
начался именно с MLX OOM («Не хватило памяти — выгрузи LM Studio»). Явный
язык убирает один MLX-проход на каждое окно.

## 2. Решение

### Новая настройка `live_subs_language` (дефолт `"ru"`)

Допустимые значения: `"ru"`, `"es"`, `"en"`, `"auto"`.

- Конкретный код → передаётся как `lang_hint` в `transcribe()`.
  `STTRouter.select_model` документирует: «Если hint_language задан явно →
  использует его напрямую» — то есть для `"ru"` маршрут детерминированно
  уходит на GigaAM (при `stt_gigaam_enabled=True`), автодетекция не
  запускается вовсе.
- `"auto"` → прежнее поведение (детекция на каждом окне). Оставлено как
  явный откат, а не удалено.

Дефолт `"ru"` — язык владельца (80%+ RU по документации роутера); для
иностранного видео переключается в настройках.

### Плюс: `context_free=True` остаётся

Для `"auto"`/`"en"`/`"es"` путь по-прежнему может уйти на Whisper —
защита от утечки промпта нужна и там. Не откатываем.

## 3. Осознанно НЕ в скоупе

- **Автоматическое определение языка «один раз на сессию» вместо каждого
  окна.** Выглядит как золотая середина, но требует решить, что делать при
  смене языка в середине видео, и добавляет состояние сессии. Явная
  настройка проще и предсказуемее; кандидат в отдельную волну, если
  владельцу надоест переключать вручную.
- Смена `TRANSCRIBE_PROMPT` (нужен A/B-замер — отдельная волна).
- Root cause MLX-OOM (среда: 36 ГБ + LM Studio + whisper-large-v3).

## 4. Риски и их закрытие

- **GigaAM не поднят / упал** → у роутера уже есть fallback-цепочка на
  Whisper; `lang_hint="ru"` не обязывает GigaAM быть живым. Отдельный тест:
  при недоступном GigaAM путь не падает, а деградирует на Whisper.
- **Иностранное видео при `live_subs_language="ru"`** → пользователь
  получит мусор. Это осознанный trade-off явной настройки; смягчается тем,
  что переключатель на виду в настройках live-субтитров.
- **GigaAM 25-секундный shortform-лимит** — окна live subs ~3с, лимит не
  задевается (chunker не нужен).

## 5. DoD

- `live_subs_language` в `DEFAULT_SETTINGS` + валидатор (enum, не диапазон).
- `_process_window` передаёт `lang_hint` при конкретном языке и НЕ передаёт
  при `"auto"` (тест на обе ветки).
- При `"ru"` и живом GigaAM автодетекция языка НЕ вызывается (тест через
  spy на `AudioLanguageID`/роутер — доказать отсутствие вызова, а не
  «результат похож»).
- При недоступном GigaAM путь деградирует на Whisper без исключения.
