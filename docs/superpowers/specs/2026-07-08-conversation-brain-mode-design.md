# Волна 3b — «Сквозняк до мозга»: brain_mode для «Разговора с AI»

Дата: 2026-07-08 · Статус: одобрено владельцем, спека закрыта, план реализации — следующий шаг
Контекст: `docs/ROADMAP-2026H2.md` §2 Волна 3, подволна 3b.

## 1. Проблема

Живой аудит 2026-07-08 подтвердил: сценарий «Краб → разговор → мозг → голосовой ответ»
технически работает end-to-end, но «мозг» по умолчанию — НЕ Main Krab. Voice Gateway
(`app/brain_chain.py::build_brain_clients`) строит цепочку провайдеров по `va_brain_order`
(дефолт `"local,gemini,openclaw"`) — Main Krab (`openclaw`-провайдер) стоит последним
фоллбэком, это осознанное решение VG-сессии (коммит `ac330a2`, июнь 2026): прямой вызов
провайдера быстрее и не зависит от OpenClaw-gateway, который «медленный и игнорит
system-prompt».

Роадмап описывает флагманский сценарий именно как «мозг Krab» — то есть Main Krab с его
памятью/MCP-инструментами/Telegram-контекстом, а не generic LLM. Владелец хочет ручной
выбор (тумблер) между «быстро» и «настоящий Краб», плюс автоматический режим-компромисс.

## 2. Область действия

Только conversation-флоу «Разговор с AI» (`app/routers/conversation.py`, WS
`/v1/sessions/{id}/conversation`). Не затрагивает PSTN-звонки и другие VG-фичи,
использующие `build_brain_clients()`/`BrainProxy` в других местах.

Проект пересекает три независимых репозитория/сессии:
- **Krab Ear** (эта сессия) — Swift UI тоггла, план реализации ниже.
- **Voice Gateway** (параллельная сессия владельца) — settings API + переупорядочивание
  цепочки + timeout/fallback-логика. Контракт зафиксирован в
  `docs/design-briefs/2026-07-08-vg-conversation-brain-mode.md`, передан владельцем.
- **Main Krab** (параллельная сессия владельца) — подтверждение/доработка обработки
  voice-style system-prompt и доступа к памяти через OpenClaw operator-scope. Контракт —
  `docs/design-briefs/2026-07-08-main-krab-voice-mode.md`, передан владельцем.

Krab Ear-план реализации (следующий шаг после этой спеки) покрывает ТОЛЬКО Swift-часть.
VG/Main-Krab работа отслеживается через брифы, не через план в этом репозитории.

## 3. Три режима (`brain_mode`)

| Режим | Порядок провайдеров | Timeout (дефолт, настраиваемый) | Поведение при таймауте |
|---|---|---|---|
| `fast` | как сейчас (`va_brain_order`) | — (не меняется) | — |
| `krab` | `openclaw` первым | 30с (`va_conversation_brain_timeout_krab_sec`) | Честный локализованный фоллбэк-текст, БЕЗ смены провайдера — пользователь явно выбрал Krab |
| `auto` (дефолт) | `openclaw` первым | 12с (`va_conversation_brain_timeout_auto_sec`) | Тихий graceful fallback на `fast`-цепочку ТОЛЬКО для этого хода; следующая реплика снова пробует Krab |

Цифры — стартовые дефолты для калибровки живым смоком, не финальные константы.

## 4. Транспорт режима (VG-контракт, для справки — реализует VG-сессия)

- `GET/PUT /v1/settings/conversation` → `{brain_mode}` — серверный дефолт (in-memory).
- WS `/v1/sessions/{id}/conversation?brain_mode=fast|krab|auto` — опциональный per-session
  override, побеждает над серверным дефолтом. Krab Ear ВСЕГДА передаёт его явно.

## 5. Krab Ear / Swift-сторона (эта сессия — реализуется по плану)

- **UI**: сегмент-контрол (Fast / Krab / Auto) в Conversation-табе рядом с кнопкой старта
  разговора. Использовать `KrabEarTheme`-токены, паттерн `ThemeButton`/существующих
  контролов таба, НЕ отдельный дизайн-брифинг agy (это behavior-код, не визуальный дизайн —
  граница из CLAUDE.md "Frontend/Design ТОЛЬКО через Gemini": если понадобится именно
  ВИЗУАЛЬНАЯ полировка контрола — отдельный шаг через agy позже, не блокирует эту волну).
- **Персистентность выбора**: `UserDefaults`, ключ по паттерну `CollapsibleSection_{id}`
  (например `KrabEar_ConversationBrainMode`), дефолт `"auto"` при первом запуске.
- **Передача в WS**: URL-конструктор в `HistoryPanelController+VoiceTab.swift:59-79`
  дополняется query-параметром `brain_mode=<выбор>` при каждом старте разговора.
- **«Сделать дефолтом»**: отдельная кнопка/действие, дёргающая `PUT /v1/settings/conversation`
  на VG (off-main IPC-паттерн — здесь это прямой HTTP-вызов к VG, не Krab Ear IPC, следуя
  уже существующему прямому WS-подключению `ConversationViewController+WebSocket.swift`).
- **Статус ожидания**: отдельного «thinking»-события в WS-протоколе (`ConvEventType` в
  `app/conversation/events.py`) нет и добавлять его не нужно (YAGNI) — существующий разрыв
  между `conv.transcript_final` (реплика пользователя распознана) и `conv.reply_final`
  (ответ мозга готов) уже даёт всё необходимое. Swift ставит статус-лейбл
  `ConversationViewController` на «Думаю…» локально по получении `conv.transcript_final` и
  снимает его по `conv.reply_final`/`conv.error`. Полноценный статус-оверлей
  (слушаю/думаю/говорю) — отдельная задача 3c, здесь только текстовый штрих на существующем
  лейбле.

## 6. Ошибки и границы

- Если VG's `/v1/settings/conversation` ещё не существует (VG-сессия не успела реализовать
  раньше Krab Ear) — Swift UI не должен падать: кнопка «Сделать дефолтом» просто получает
  404/timeout, показывает ненавязчивую ошибку, сам query-param `brain_mode` в WS-URL
  продолжает работать независимо (если VG уже поддерживает хотя бы query-param, но не
  settings API — частичная функциональность лучше полного отказа).
- Если `brain_mode` не поддерживается VG вообще (query-param игнорируется старой версией) —
  поведение не хуже текущего (VG просто продолжит использовать `fast`-цепочку по умолчанию).

## 7. Тестирование

- Swift: unit-тест на построение WS-URL с корректным `brain_mode` query-параметром для
  каждого из 3 значений; тест на персистентность `UserDefaults` выбора между запусками.
- Живой e2e-смок (координированно с VG-сессией, когда её часть готова): реальный разговор в
  каждом из 3 режимов, зафиксировать наблюдаемую латентность Main Krab, при необходимости
  скорректировать дефолты таймаутов в брифе задним числом.

## 8. Не в скоупе этой волны

- Полноценный статус-оверлей «слушаю/думаю/говорю» — Волна 3c.
- Персистентность `brain_mode` на стороне VG за пределами in-memory (диск/БД) — на
  усмотрение VG-сессии, не блокирует эту волну.
- Визуальная полировка нового UI-контрола через agy — при необходимости отдельным шагом.
