## 1. Scope

Phase 2.2 adds a **fifth tab "Live Перевод"** to the Krab Ear `.app` macOS window. It is the Swift/macOS client side of the Live Translation feature. The backend WS endpoint `/v1/translation/stream` is implemented in Phase 2.1 (Voice Gateway); Phase 2.2 consumes it.

**In scope:**

- New tab "Live Перевод" registered in `HistoryPanelController`
- Audio source picker (System Audio / Microphone / BlackHole)
- Source language + target language dropdowns (RU, EN, ES, auto-detect)
- Start/Stop translation button with state-driven label
- Split-screen subtitle display: source language top pane / target language bottom pane
  - `seq_id`-based replace-in-place for partials (no flicker)
- Waveform overlay strip at the bottom (reuse `RealtimeOverlayController` wave component)
- Latency badge and confidence indicator per utterance
- Session history list (populated on `translation.session_saved` events)
- State machine: Idle → Connecting → Streaming → Paused → Error → Idle

**Out of scope for 2.2:**

- Floating ribbon overlay (v1.1, Phase 2.6)
- Glossary tooltip on hover (Phase 2.4 — separate PR)
- Hotkey trigger for Live Translation (Phase 2.6)
- ScreenCaptureKit audio capture implementation (Phase 2.4)
- Backend engine changes (Phase 2.1, Voice Gateway repo)

## 4. Event Contracts — Pydantic → Swift Codable Mapping

The Phase 2.1 VG endpoint emits 7 JSON event types. Swift `Codable` mapping:

### 4.1 Downlink events (VG → Krab Ear)

```
translation.engine_ready
  Python: {"type": "translation.engine_ready", "engine": str, "elapsed_s": float}
  Swift:  TranslationEngineReadyEvent(type, engine: String, elapsedSeconds: Double)

translation.lang_detected
  Python: {"type": "translation.lang_detected", "source_lang": str, "confidence": float}
  Swift:  TranslationLangDetectedEvent(type, sourceLang: String, confidence: Double)

translation.partial
  Python: {"type": "translation.partial", "seq_id": int, "source_text": str, "target_text": str,
           "source_lang": str, "target_lang": str, "confidence": float, "latency_ms": int}
  Swift:  TranslationPartialEvent(type, seqId: Int, sourceText: String, targetText: String,
                                  sourceLang: String, targetLang: String,
                                  confidence: Double, latencyMs: Int)

translation.final
  Python: {"type": "translation.final", "seq_id": int, "source_text": str, "target_text": str,
           "source_lang": str, "target_lang": str, "confidence": float, "latency_ms": int}
  Swift:  TranslationFinalEvent(type, seqId: Int, sourceText: String, targetText: String,
                                sourceLang: String, targetLang: String,
                                confidence: Double, latencyMs: Int)

translation.session_saved
  Python: {"type": "translation.session_saved", "session_id": str, "duration_s": float,
           "utterance_count": int, "source_lang": str, "target_lang": str}
  Swift:  TranslationSessionSavedEvent(type, sessionId: String, durationSeconds: Double,
                                       utteranceCount: Int, sourceLang: String, targetLang: String)

translation.error
  Python: {"type": "translation.error", "code": str, "message": str, "recoverable": bool}
  Swift:  TranslationErrorEvent(type, code: String, message: String, recoverable: Bool)
```

### 4.2 Uplink messages (Krab Ear → VG)

```
stream.config (sent once after WS open, before audio)
  Swift:  TranslationStreamConfig(type: "stream.config", sourceLang: String, targetLang: String,
                                  audioSource: String)
  JSON:   {"type": "stream.config", "source_lang": "ru", "target_lang": "en", "audio_source": "mic"}

pause / resume
  Swift:  TranslationControlMessage(type: "pause" | "resume")

end
  Swift:  TranslationControlMessage(type: "end")
```

### 4.3 Discriminated union dispatch

`TranslationEvent` enum with associated values dispatched by `"type"` field in `decode(from:)` static method — same pattern as `ConversationEvent` in Phase 1.

```
enum TranslationEvent {
    case engineReady(TranslationEngineReadyEvent)
    case langDetected(TranslationLangDetectedEvent)
    case partial(TranslationPartialEvent)
    case final_(TranslationFinalEvent)
    case sessionSaved(TranslationSessionSavedEvent)
    case error(TranslationErrorEvent)
    case unknown(type: String, raw: Data)
}
```

```
│                              │                           │

│                              │                           │
│                              ▼                           │

│                              │                        │  │
```

```swift
enum TranslationState: Equatable {
    case idle
    case connecting
    case streaming
    case paused
    case error(String)
```

- Row click: expands inline to show full transcript (both panes) using `CollapsibleSectionView` pattern

## 7. `SubtitleRendererView` — Replace-in-Place Logic

The key UX challenge is displaying streaming partials without flicker. Strategy:

1. Maintain `currentSeqId: Int = -1` and `partialRange: NSRange?`
2. On `translation.partial(seqId, sourceText, targetText)`:
   - If `seqId == currentSeqId`: replace text in `partialRange` in-place (no append, no scroll jump)
   - If `seqId > currentSeqId`: append finalized previous line (if any), start new partial with `currentSeqId = seqId`
   - Display partial in `textSecondary` color with trailing "…"
3. On `translation.final(seqId, sourceText, targetText)`:
   - Replace partial range with final text, reset to `primaryLabel` color
   - Clear `partialRange`, increment `currentSeqId`
   - Trigger scroll-to-bottom with `Motion.Duration.micro` animation

Both top (source) and bottom (target) panes use the same logic independently.

## 8. `TranslationStreamClient` — Architecture

Thin facade over `URLSessionWebSocketTask`:

```
TranslationStreamClient
  init(wsURLString: String, apiKey: String)
  func connect(config: TranslationStreamConfig) async throws
    → opens WS, sends stream.config JSON, starts receive loop
  func disconnect() async
    → sends "end" control, closes WS task
  func sendAudioFrame(_ data: Data)
    → binary uplink, fire-and-forget
  func sendControl(_ control: TranslationControlMessage)
    → JSON text uplink
  var events: AsyncStream<TranslationEvent>
    → continuation fed by receive loop
```

The `AsyncStream<TranslationEvent>` is consumed by `LiveTranslationViewController` in an `async for` loop on `Task { @MainActor in ... }`.

This is a deliberate mirror of the WS pattern in `ConversationViewController+WebSocket.swift`, factored as a standalone class (not an extension) so it can be unit-tested in isolation.

## 9. UX Flows

### 9.1 Happy path — start translation

1. User opens "Live Перевод" tab (index 4)
2. Selects audio source: Microphone (default)
3. Selects source lang: RU (default from last session, persisted in UserDefaults)
4. Selects target lang: EN (default)
5. Taps "Начать перевод"
6. State → `.connecting`; button disabled; status: "🟡 Подключение…"
7. `TranslationStreamClient.connect()` opens WS, sends `stream.config`
8. VG responds `translation.engine_ready` → state → `.streaming`; status: "🟢 Переводит"
9. Audio capture starts via `AVAudioEngine` (microphone)
10. Audio frames sent via `sendAudioFrame(_:)` at 200ms intervals
11. Partials arrive → `SubtitleRendererView` updates in real-time
12. Finals replace partials in-place; metrics footer updates
13. Waveform strip pulses with RMS amplitude

### 9.2 Stop translation

1. User taps "Завершить"
2. `sendControl(.end)` sent to VG
3. Audio capture stops
4. WS receives `translation.session_saved` → session appended to history list
5. WS closes; state → `.idle`

### 9.3 Error recovery (recoverable)

1. VG sends `translation.error(code: "inference_timeout", recoverable: true)`
2. State → `.error("inference_timeout")`; status badge: "🔴 Ошибка: inference_timeout"
3. Button label changes to "Повторить"
4. Waveform strip goes flat
5. User taps "Повторить" → `reconnect()`: closes old WS, opens new WS, re-sends `stream.config`
6. State → `.connecting` → `.streaming`

### 9.4 Error — non-recoverable

1. VG sends `translation.error(code: "audio_source_unavailable", recoverable: false)`
2. State → `.error(message)` with informational subtitle shown above button
3. Button: "Закрыть" → tapped → state → `.idle`, audio released
4. User directed to audio source picker to choose alternative

### 9.5 Language switch mid-session

1. User changes target lang dropdown during `.streaming`
2. Controller sends `sendControl(.end)`, waits for `session_saved`
3. Clears subtitle panes
4. Immediately calls `connect()` with new `stream.config`
5. New session starts — no idle gap from user perspective (background reconnect)
6. Brief "🟡 Подключение…" status during reconnect (~500ms)

### 9.6 Pause / Resume

1. User taps "Пауза" button (visible during `.streaming`)
2. `sendControl(.pause)` → audio capture stops
3. State → `.paused`; status: "🟡 Пауза"; waveform flat; pause button label → "Продолжить"
4. WS remains open (VG keeps engine warm for 5 min)
5. User taps "Продолжить" → `sendControl(.resume)` → audio capture restarts → state → `.streaming`

## 10. Swift 6 Strict Concurrency Notes

The project uses `swift-tools-version: 6.0` with strict concurrency enabled. Key constraints for Phase 2.2:

1. **`@MainActor` isolation**: `LiveTranslationViewController` and `SubtitleRendererView` are `@MainActor final class`. All UI mutations must happen on MainActor.

2. **WS receive loop**: `TranslationStreamClient` itself is not `@MainActor`. The `URLSessionWebSocketTask.receive` callback fires on an arbitrary thread. Feed events via `AsyncStream.Continuation` (safe — continuations are `Sendable`). The consuming `async for` loop on the ViewController side runs in a `Task { @MainActor in ... }` — this is safe.

3. **Audio callback**: `AVAudioEngine` tap callback fires on a background audio thread. Call `waveformView.updateAmplitude()` via `Task { @MainActor in ... }` (same pattern as `RealtimeOverlayController` pulse timer).

4. **`WSHolder` pattern**: If the split-WS-holder approach from `ConversationViewController+WebSocket.swift` is reused (associated objects in extension), `TranslationStreamClient` as a standalone class avoids this complexity entirely — preferred.

5. **`nonisolated(unsafe)` keys**: Static `UInt8` associated-object keys follow the same pattern already established in `HistoryPanelController+VoiceTab.swift`.
