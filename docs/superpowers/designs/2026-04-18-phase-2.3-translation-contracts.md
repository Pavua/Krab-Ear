## Context

Phase 2.1 (PR #52) defines the Voice Gateway WebSocket endpoint `/v1/translation/stream` with 7 downlink JSON events:

| Event type | Direction | Description |
|---|---|---|
| `translation.partial` | VG → Krab Ear | Incremental text (source or target lang) |
| `translation.transcript` | VG → Krab Ear | Committed source-lang transcript per utterance |
| `translation.final` | VG → Krab Ear | Committed translated text per utterance |
| `translation.engine_ready` | VG → Krab Ear | Engine loaded and warmed up |
| `translation.lang_detected` | VG → Krab Ear | Auto-detected source language |
| `translation.session_saved` | VG → Krab Ear | Session persisted to Krab Ear history |
| `translation.error` | VG → Krab Ear | Processing error (fatal or non-fatal) |

Phase 2.3 brings these events into the Krab Ear `contracts/` layer:
- Pydantic models with field-level validation
- `EventType` enum extensions
- `EVENT_SCHEMA_MAP` entries
- JSON Schema export to `contracts/schemas/`
- Backward-compat guarantee (existing `translation.completed` / `translation.failed` untouched)

**EventType enum (8 values):**
`stt.partial`, `stt.final`, `stt.failed`, `translation.completed`, `translation.failed`,
`markdown_export`, `auto_summary`, `hotword.detected`

**Key constraint:** `translation.completed` and `translation.failed` are **batch-mode** events
(single transcription → translate → emit once). The 7 new streaming events have different
semantics (incremental, per-utterance, session lifecycle) and MUST NOT replace or
conflict with the existing pair.

## New Files

### `contracts/streaming_translation_events.py` (new)

Separate module from `translation_events.py` to make the batch/streaming boundary explicit.

Rationale for separate file (not appending to `translation_events.py`):
- Batch models (`TranslationCompleted`, `TranslationFailed`) have `history_id` as a
  primary key tying them to the StateStore. Streaming models are session-scoped with
  `seq_id` and `session_id`.
- Import graph stays clean: `backend/translation_service.py` imports only
  `translation_events.py`; the new `backend/vgws_client.py` imports only
  `streaming_translation_events.py`.
- Avoids a 200-line monolith that mixes two different contract generations.

## Pydantic Model Specifications

All models inherit `pydantic.BaseModel`. All fields use strict types (no `Any`).
Optional fields default to `None` unless a safer default is noted.

The envelope (`{type, ts, data}`) is handled by `KrabEventEnvelope` in `envelope.py` —
these models describe only the `data` dict payload.

### 1. `TranslationPartialData`

Emitted repeatedly as the engine produces incremental text. Used for both source-language
partial transcripts and target-language partial translations (distinguished by `lang` field).

```python
class TranslationPartialData(BaseModel):
    seq_id: str            # UUID, utterance identifier; same seq_id = replace previous partial
    lang: str              # BCP-47 language code: "ru", "en", "es"
    text: str              # Partial text so far (may be empty string on first token)
    confidence: float | None = None   # 0.0–1.0; None if not available yet
    latency_ms: int | None = None     # ms from first audio frame to this token
    session_id: str | None = None     # VG session UUID (propagated for multi-session UIs)
```

**Validation rules:**
- `lang` — 2-3 character code (regex `^[a-z]{2,3}$`); validated in impl with `Field(pattern=...)`
- `confidence` — `ge=0.0, le=1.0` if present
- `latency_ms` — `ge=0` if present

### 2. `TranslationTranscriptData`

Committed (final) source-language transcript for one utterance. Appended to session log.

```python
class TranslationTranscriptData(BaseModel):
    seq_id: str            # Same UUID as the partials for this utterance
    lang: str              # Source language code
    text: str              # Final transcript text (non-empty)
    confidence: float | None = None
    offset_ms: int = 0     # ms from session start to utterance start
    duration_ms: int       # ms of speech duration for this utterance
    session_id: str | None = None
```

**Validation rules:**
- `text` — `min_length=1` (committed transcripts must have content)
- `duration_ms` — `ge=1`
- `offset_ms` — `ge=0`

### 3. `TranslationFinalData`

Committed (final) translated text in the target language for one utterance.

```python
class TranslationFinalData(BaseModel):
    seq_id: str            # Same UUID as transcript + partials for this utterance
    lang: str              # Target language code
    text: str              # Final translated text
    source_lang: str       # Source language (denormalized for consumer convenience)
    confidence: float | None = None
    latency_ms: int | None = None     # ms from utterance start to final translation
    session_id: str | None = None
```

**Validation rules:**
- `text` — `min_length=1`
- `lang != source_lang` is expected but NOT enforced at model level (same-lang pass-through
  is valid for transcript mode)

### 4. `TranslationEngineReadyData`

Emitted once per session after the SeamlessStreaming engine is loaded and warmed up.
The Swift client waits for this event before showing the "live" indicator in the overlay.

```python
class TranslationEngineReadyData(BaseModel):
    engine: str            # Engine identifier: "seamless_streaming_2.5b" | "seamless_m4t_v2_large" | "fallback_local"
    source_lang: str       # Configured source language ("auto" if auto-detect mode)
    target_lang: str       # Configured target language
    warmup_ms: int         # ms from session open to engine ready
    session_id: str | None = None
```

**Validation rules:**
- `warmup_ms` — `ge=0`
- `engine` — no enum constraint at Pydantic level (new engines may be added); validated
  at application layer

### 5. `TranslationLangDetectedData`

Emitted after the first ~1.5s of audio when auto-detection mode is active.

```python
class TranslationLangDetectedData(BaseModel):
    source_lang: str       # Detected language code
    confidence: float      # 0.0–1.0 detection confidence
    session_id: str | None = None
```

**Validation rules:**
- `confidence` — `ge=0.0, le=1.0` (required field — detection always provides a score)
- `source_lang` — `min_length=2`

### 6. `TranslationSessionSavedData`

Emitted when the session ends and VG has persisted the session transcript to Krab Ear
history (via IPC `save_translation_session` call).

```python
class TranslationSessionSavedData(BaseModel):
    history_id: str           # Krab Ear StateStore entry UUID
    duration_sec: float       # Total session duration in seconds
    word_count_original: int  # Word count of the source transcript
    word_count_translated: int  # Word count of the translated output
    session_id: str | None = None
```

**Validation rules:**
- `duration_sec` — `ge=0.0`
- `word_count_original` — `ge=0`
- `word_count_translated` — `ge=0`

### 7. `TranslationStreamErrorData`

Non-fatal or fatal error during streaming. Fatal errors close the WebSocket after emission.

**Name note:** cannot use `TranslationErrorData` — would shadow the existing batch
`TranslationFailed` semantics in any code that does `from contracts.streaming_translation_events import *`.
Using `TranslationStreamErrorData` is unambiguous.

```python
class TranslationStreamErrorData(BaseModel):
    code: str              # Error code (see table below)
    message: str           # Human-readable description
    fatal: bool            # True → WS closes after this event; False → processing resumes
    session_id: str | None = None
```

**Standard error codes (documented, not enforced in model):**

| Code | Fatal | Description |
|---|---|---|
| `inference_timeout` | False | Engine took >5s for one utterance; retry next |
| `audio_source_unavailable` | True | Microphone permission denied or device disconnected |
| `engine_load_failed` | True | Model checkpoint missing or OOM on load |
| `unsupported_lang_pair` | True | Requested `(source_lang, target_lang)` pair not supported |
| `session_not_found` | True | `session_id` was provided but not in VG SessionStore |
| `buffer_overflow` | False | PCM buffer exceeded 30s without VAD segment; flushed |

## Event Envelope

All 7 events use the existing `EVENT_CONTRACT_V1` envelope — no changes to `envelope.py`:

```jsonc
{
  "type": "translation.partial",   // EventType string value
  "ts": 1745001234.1,              // UNIX epoch float (seconds, fractional)
  "data": { /* model fields */ }
}
```

`ts` is a UNIX epoch `float` in the wire protocol (matching Phase 2.1 spec).
`KrabEventEnvelope` stores it as `datetime` after `parse_event()` — the Pydantic coercion
`datetime` ← `float` is handled by `pydantic` v2's `model_validator`.

**Backward compat:** existing `parse_and_validate()` raises `UnknownEventType` for any
`type` not in `EventType`. After Phase 2.3, `translation.partial` etc. are registered —
callers that previously caught `UnknownEventType` for these strings must update their
catch logic if they want to handle streaming events. The existing batch events are
unaffected.

## JSON Schema Export

### Command (unchanged interface)

```bash
# From repo root, with venv active:
PYTHONPATH=$(pwd)/KrabEar python -m contracts.export --output KrabEar/contracts/schemas/
```

The `export.py` script iterates `EVENT_SCHEMA_MAP` and calls `.model_json_schema()` on
each model class. No changes to `export.py` are required — adding entries to
`EVENT_SCHEMA_MAP` automatically includes them in export.

### Output files (7 new schemas)

```
contracts/schemas/
  ...existing files...

  translation.final.schema.json
  translation.engine_ready.schema.json
  translation.lang_detected.schema.json
  translation.session_saved.schema.json
  translation.error.schema.json
```

### Example: `translation.partial.schema.json` (illustrative)

```json
{
  "title": "TranslationPartialData",
  "description": "Partial translation text — incremental update for one utterance.",
  "type": "object",
  "properties": {
    "seq_id":      { "type": "string", "title": "Seq Id" },
    "lang":        { "type": "string", "title": "Lang", "pattern": "^[a-z]{2,3}$" },
    "text":        { "type": "string", "title": "Text" },
    "confidence":  { "anyOf": [{"type": "number", "minimum": 0.0, "maximum": 1.0}, {"type": "null"}], "default": null },
    "latency_ms":  { "anyOf": [{"type": "integer", "minimum": 0}, {"type": "null"}], "default": null },
    "session_id":  { "anyOf": [{"type": "string"}, {"type": "null"}], "default": null }
  },
  "required": ["seq_id", "lang", "text"]

```

### Combined export (optional — for Swift codegen)

```bash
# Single file with all translation streaming schemas bundled
PYTHONPATH=$(pwd)/KrabEar python - <<'EOF'
import json
from pathlib import Path
from contracts.registry import EVENT_SCHEMA_MAP, EventType

streaming_types = {
    EventType.TRANSLATION_PARTIAL,
    EventType.TRANSLATION_TRANSCRIPT,
    EventType.TRANSLATION_FINAL,
    EventType.TRANSLATION_ENGINE_READY,
    EventType.TRANSLATION_LANG_DETECTED,
    EventType.TRANSLATION_SESSION_SAVED,
    EventType.TRANSLATION_STREAM_ERROR,
}
bundle = {
    et.value: cls.model_json_schema()
    for et, cls in EVENT_SCHEMA_MAP.items()
    if et in streaming_types
}
Path("contracts/schemas/translation_streaming_v1.json").write_text(
    json.dumps(bundle, indent=2, ensure_ascii=False)
)
EOF
```

Output: `contracts/schemas/translation_streaming_v1.json` — 7 schemas keyed by event type string.

## JSON Schema Usage

### 1. Swift codegen (`TranslationEventTypes.swift`)

**Phase 2.4** (Swift WS client) will consume the JSON schemas to generate Swift `Codable`
structs. Workflow:

1. Run combined export → `translation_streaming_v1.json`
2. Use `quicktype` or hand-write Swift structs matching the schema
3. Structs go into `native/KrabEarAgent/TranslationEventTypes.swift`
4. `RealtimeOverlayController` decodes incoming WS frames using these structs

Each schema property maps 1:1 to a Swift struct field. Optional Pydantic fields
(`None` default) map to `Optional<T>` in Swift.

**Naming convention:**

| Python model | Swift struct |
|---|---|
| `TranslationPartialData` | `TranslationPartialPayload` |
| `TranslationFinalData` | `TranslationFinalPayload` |
| `TranslationEngineReadyData` | `TranslationEngineReadyPayload` |
| ... | ... |

The suffix `Payload` avoids collision with any existing Swift types named `TranslationFinal`.

### 2. Python runtime validation (VGWSClient)

`backend/vgws_client.py` (Phase 2.4 backend) will use `parse_and_validate()` from
`envelope.py` to validate incoming WS frames:

```python
from contracts.envelope import parse_and_validate, UnknownEventType
from pydantic import ValidationError

raw = json.loads(ws_message)
try:
    event_type, payload = parse_and_validate(raw)
except UnknownEventType:
    logger.warning("unknown_event_type", type=raw.get("type"))
except ValidationError as e:
    logger.error("invalid_event_payload", errors=e.errors())
else:
    await event_bus.emit_typed(event_type, payload)
```

The validated `payload` is a concrete model instance (e.g., `TranslationPartialData`)
with type-safe field access.

### 3. Documentation auto-generation

`python -m contracts.export` already produces per-file schemas. CI can publish these
to a `/docs/schemas/` static site (GitHub Pages) for VG ↔ Krab Ear contract visibility.

Future: add `--format markdown` flag to `export.py` to emit a human-readable contract
table alongside the JSON files.

`EventType.TRANSLATION_STREAM_ERROR` (enum name differs from string value deliberately).

the wire format exactly as specified in Phase 2.1 (`"translation.error"`).

## Testing Plan

### Unit tests: `KrabEar/tests/test_translation_contracts.py`

**PR 2.3.1 — model roundtrip tests (one per model):**

```python
def test_translation_partial_roundtrip():
    data = {"seq_id": "abc123", "lang": "ru", "text": "Привет", "confidence": 0.91}
    m = TranslationPartialData.model_validate(data)
    assert m.seq_id == "abc123"
    assert m.lang == "ru"

    with pytest.raises(ValidationError):

    m = TranslationStreamErrorData.model_validate({

    raw = {"type": "translation.partial", "ts": 1745001234.1,
           "data": {"seq_id": "x1", "lang": "en", "text": "Hello"}}
    etype, payload = parse_and_validate(raw)
    assert etype == EventType.TRANSLATION_PARTIAL
    assert isinstance(payload, TranslationPartialData)
```

## Summary

Phase 2.3 adds **7 new Pydantic models** and **7 new EventType enum values**, bringing the
total registered contract count from 8 to 15. All changes are additive — no existing
contract is modified. The JSON Schema export pipeline requires zero changes; new schemas
are emitted automatically. Two focused PRs (2.3.1 models, 2.3.2 export) keep review
surfaces small (~90 + ~30 lines of Python each).
