## Обзор

`TTSService` реализует трёхуровневую fallback-цепочку синтеза речи:

1. **Silero** — PyTorch-модель (`v4_ru`), primary для Russian.
2. **Kokoro-82M** — Apache-2.0 pipeline (`hexgrad/Kokoro-82M`), primary для English.
3. **macOS `say`** — последний резерв через `afconvert` AIFF→WAV.

По умолчанию `TTS_ENABLED=False` — вся продакшн-нагрузка идёт через `say`. ML-цепочка opt-in.

---

## 1. Логика выбора движка

### Fallback chain (`synthesize_speech`)

```
language == "auto" → _detect_language(text)
          │
          ├── "ru"  → Silero → (if None) → macOS say
          └── "en"  → Kokoro → (if None) → Silero → (if None) → macOS say
```

**Корректно:** для RU Kokoro не вызывается (Kokoro не поддерживает русский). Для EN Silero используется как промежуточный fallback, поскольку `v4_ru` умеет базовый EN.

**Находка F-1 (LOW):** Silero загружается как `language="ru"` в `torch.hub.load` (строка 58). Попытка синтезировать английский текст через Silero-RU модель произведёт акцентированный/искажённый вывод. Поведение не задокументировано в строке `_synthesize_silero` — нет предупреждения что EN через RU-Silero — деградированный режим.

**Находка F-2 (LOW):** При `language` отличном от `"ru"` и `"en"` (например `"es"`) — код попадает в EN-ветку (строка 280: `else:`). Испанский текст пойдёт через Kokoro EN → Silero RU → say. Нет явной обработки третьих языков, нет предупреждения в логах.

## 2. Определение языка (`_detect_language`)

**Алгоритм:** доля кириллических символов (U+0400–U+04FF) среди всех `isalpha()` символов. Порог 30%.

**Корректно:** быстро, без зависимостей, детерминировано. Threshold 30% разумен для смешанных RU+латинских текстов (аббревиатуры, имена).

**Находка F-3 (LOW):** Диапазон U+0400–U+04FF включает не только русский, но и украинский, болгарский, сербский кириллические символы. Для них будет выбрана RU-цепочка (Silero RU). Это приемлемо для текущего use-case (RU primary), но не задокументировано.

**Находка F-4 (LOW):** Пустая строка и строки из цифр/пунктуации возвращают `"en"` (нет `alpha_chars`). Это корректный fallback, но поведение неочевидно: `"12345"` → `"en"` → Kokoro попытается синтезировать цифры как английский текст. `say` справится лучше с цифрами.

## 3. Обработка ошибок и fallback

### Lazy loaders (`_load_silero`, `_load_kokoro`)

- `ImportError` → `DEBUG` лог, `None` — ОК.
- Любое другое исключение → `WARNING` лог, `None` — ОК.
- Double-checked locking через `_silero_attempted` / `_kokoro_attempted` флаги — thread-safe.

**Находка F-5 (MEDIUM):** После первой неудачной попытки загрузки (`_silero_attempted = True`, `_silero = None`) модель **никогда не будет перезагружена** в рамках жизни процесса. Если torch был временно недоступен при старте (например, модель ещё скачивалась), пользователь не сможет включить Silero без перезапуска бэкенда. Нет IPC-метода `reload_tts_models`. Для production это некритично при стабильной среде, но стоит задокументировать.

### `_synthesize_silero` / `_synthesize_kokoro`

- Оба ловят все исключения через `except Exception` → `WARNING` лог → `None`.
- Это правильно: гарантирует продвижение по fallback-цепочке.

### `_say_to_wav`

- Запускает `say` и `afconvert` через `subprocess.run` с `check=False`.
- **Находка F-6 (MEDIUM):** `check=False` означает что ошибка `say` или `afconvert` замалчивается. Если AIFF файл не создан или пустой, функция проверяет `os.path.getsize(wav_path) > 0` и возвращает `b""`. Но между `subprocess.run(cmd_say)` и `subprocess.run(afconvert)` нет проверки успешности первого шага — `afconvert` будет запущен даже если `say` упал. В результате `afconvert` пытается конвертировать несуществующий/пустой AIFF, тихо падает, и функция возвращает `b""` без объяснения в логах.

**Рекомендация для F-6:** добавить проверку `os.path.getsize(aiff_path) > 0` после `say`, с `WARNING` логом перед вызовом `afconvert`.

## 4. Формат выходного аудио

| Путь | Частота дискретизации | Каналы | Глубина бит | Формат |
|------|-----------------------|--------|-------------|--------|
| Silero | динамически из `sample_rate` (обычно 24000 Hz) | 1 (моно) | 16-bit PCM | WAV |
| Kokoro | хардкод 24000 Hz (строка 216) | 1 (моно) | 16-bit PCM | WAV |
| macOS say + afconvert | хардкод 22050 Hz (строка 115: `LEF32@22050`) | зависит от afconvert | 32-bit float → WAV | WAV |

**Находка F-7 (MEDIUM):** Выходной формат несогласован между движками:
- Silero: sample_rate из модели (документация v4_ru указывает 24000 Hz).
- Kokoro: хардкод 24000 Hz.
- macOS say (afconvert): хардкод 22050 Hz **и** float32 (`LEF32`), при этом в WAV записывается как 16-bit PCM через `wave.open` + `np.int16` у Silero/Kokoro, но для `say` возвращается сырой float32 WAV без конверсии в int16.

Потребители WAV-байт (IPC-клиент, Swift `WakeWordListener`) должны учитывать разные sample rates. IPC-ответ не включает `sample_rate` поле — клиент не может знать формат без дополнительных запросов.

**Рекомендация для F-7:** добавить `sample_rate` и `channels` поля в ответ `handle_synthesize_speech`.

## 5. IPC handler (`handle_synthesize_speech`)

**Корректно:**
- Санитизация `language` (неизвестный язык → `"auto"`).
- Санитизация `voice` (strip, None для пустой строки).
- Возврат `{"ok": False, "error": ...}` для пустого текста.

**Находка F-8 (LOW):** Поле `engine` в ответе определяется **после** синтеза по состоянию `self._silero` / `self._kokoro` (строки 334–340), а не по фактически использованному движку. Если Silero загружен но `_synthesize_silero` упал и результат пришёл от `say`, ответ всё равно вернёт `engine="silero"`. Это false reporting.

**Рекомендация для F-8:** `synthesize_speech` должен возвращать `(bytes, engine_name: str)` tuple, чтобы `handle_synthesize_speech` сообщал реально использованный движок.

## 6. Безопасность голоса (`_say_to_wav`)

Строки 108–109: голос санитизируется regex `^[a-zA-Z0-9 _\-]+$`, при несовпадении подставляется `"Milena"`.

**Корректно:** предотвращает shell-инъекцию через имя голоса. `subprocess.run` с `list` (не `shell=True`) дополнительно защищает.

## 7. Покрытие тестами (`test_tts_service.py`)

Файл имеет 17 тест-кейсов в 4 классах. Покрыты:
- `_detect_language` — 5 кейсов (RU, EN, empty, mixed above/below threshold).
- Fallback chain (TTS disabled, TTS enabled no models, empty text, auto language).
- Engine routing (RU→Silero, EN→Kokoro, full fallback chain).
- IPC handler (base64 output, empty text error, invalid language, empty synthesis).
- Concurrency (5 threads).

**Не покрыты тестами:**
- `_load_silero` / `_load_kokoro` реальная загрузка (ожидаемо — ML env).
- `_say_to_wav` прямой вызов (shell зависимость).
- F-6: сценарий когда `say` падает (пустой AIFF).
- F-7: проверка `sample_rate` в WAV-байтах из разных движков.
- F-8: несоответствие `engine` поля реальному движку.
