# Audit W1643: backend/models.py — HistoryItem first-pass audit

**Date:** 2026-05-30
**File:** `KrabEar/backend/models.py` (190 LOC)
**Auditor:** Sub-agent W1643
**Wave context:** First dedicated audit of the central shared data model; marathon found "lost metadata field" regressions in W1047, W1237, W1542b.

---

## Summary

7 findings (2 HIGH, 3 MED, 2 LOW). The most critical is a forward-compat regression: the `_extra` sidecar pattern tested in `test_history_item_forward_compat_W1238.py` is entirely absent from the implementation. Six test methods that assert `item._extra` will fail at runtime against the current model. The second HIGH is `add_history_item()` in `state_store.py` missing 9 of the 26 HistoryItem fields, silently discarding them on initial write.

---

## Findings

### F1 HIGH — _extra sidecar tested but not implemented (test vs code divergence)

`KrabEar/tests/test_history_item_forward_compat_W1238.py` (6 test methods) was written as a fix for W1228 F2 MED to guarantee forward-compatibility of unknown fields through compaction round-trips. Every test references `item._extra`, asserts it captures unknown keys from `from_dict`, and verifies `to_dict` re-emits them at the top level. However, the current `models.py` has:

- `@dataclass(slots=True)` with no `_extra` slot defined
- `from_dict` silently ignores unknown keys (they are discarded by `payload.get()` lookups — unknown fields are never stored)
- `to_dict` uses `asdict(self)` which only serialises declared slots
- Runtime confirmation: `hasattr(item, '_extra') == False`, unknown fields absent from `to_dict` output

**Impact:** All 6 tests in `test_history_item_forward_compat_W1238.py` are failing (AttributeError on `item._extra`). Production impact: when a newer binary writes a new field to `history.ndjson` and then `_compact_unlocked` reads the record back with the older binary, the new field is silently dropped. This is the exact "lost metadata field" regression pattern seen in W1047/W1237/W1542b.

**Fix:** Add `_extra: dict = field(default_factory=dict)` slot, update `from_dict` to capture unknown keys into it, update `to_dict` to merge `_extra` contents (excluding `_extra` key itself) before returning.

**Files:** `KrabEar/backend/models.py`, `KrabEar/tests/test_history_item_forward_compat_W1238.py`

### F2 HIGH — add_history_item() in StateStore missing 9 HistoryItem fields

`StateStore.add_history_item()` (lines 166–224 of `state_store.py`) accepts and passes only 17 of the 26 fields that `HistoryItem.create()` supports. The following fields have no path from `add_history_item` to the NDJSON record:

| Missing field | Default in HistoryItem | Risk |
|---|---|---|
| `tags` | `[]` | tags silently lost on initial write; repaired by override journal only on re-read |
| `favorite` | `False` | favorites journal handles post-write, not initial |
| `audio_path` | `""` | cannot re-transcribe items that were never saved with audio_path |
| `is_protected` | `False` | bulk operations may clobber protected items |
| `reasoning` | `None` | Voxtral reasoning never persisted |
| `action_items` | `None` | override journal exists for post-write; initial write always null |
| `decisions` | `None` | same |
| `questions` | `None` | same |
| `privacy_mode` | `False` | **most critical**: privacy-mode recordings not marked as such in history.ndjson; privacy audit incomplete |

The fields `tags`, `favorite`, `action_items`, `decisions`, `questions` have post-write override journals in StateStore, so they can be set after initial creation. But `audio_path`, `is_protected`, `reasoning`, and `privacy_mode` have no journal path — what is not written on `add_history_item` is lost unless the caller patches the item object directly.

**Impact:** `privacy_mode=True` recordings are not flagged at write time. Re-transcription support (`audio_path`) is unreachable via the standard recording path. Callers that construct a `HistoryItem` manually and pass it to lower-level APIs work correctly; only the `add_history_item` convenience API is affected.

**Fix:** Add the 9 missing parameters to `add_history_item` and pass them through to `HistoryItem.create()`.

**Files:** `KrabEar/backend/state_store.py` lines 166–224

### F3 MED — ts field is timezone-naive (local time stored without offset)

`HistoryItem.create()` generates timestamps using `datetime.now().isoformat(timespec="seconds")` (line 115). This produces naive ISO-8601 like `2026-05-30T00:38:25` — no UTC offset, no `Z` suffix. On machines in non-UTC timezones, two items created minutes apart but across a DST transition will sort incorrectly. Sorting is used by StateStore for history pagination. Additionally, if a user migrates data between timezone-configured machines, absolute times shift.

The marathon history found multiple tz-related bugs (W1047, W1237). The `from_dict` path has no tz normalisation either — it stores whatever string is in the payload.

**Risk:** Sorting bugs near DST boundaries; incorrect analytics for users running Krab Ear on machines where the system timezone changes.

**Fix:** Use `datetime.now(tz=timezone.utc).isoformat(timespec="seconds")` in `create()`. Add a migration note for existing naive timestamps (treat as local-naive, no backfill required for typical usage).

**Files:** `KrabEar/backend/models.py` line 115

### F4 MED — empty id/ts not validated in from_dict (invalid items accepted silently)

`from_dict` (lines 154–186) accepts an empty-string `id` and `ts` without raising. Runtime confirmation: `HistoryItem.from_dict({"id": "", "ts": "", "text": ""})` produces `item.id == ""` and `item.ts == ""`. StateStore uses `item.id` as the primary key for tombstone matching and deduplication (`is_idempotent`). An item with `id=""` would corrupt the index — any subsequent tombstone targeting `""` would delete it alongside any other corrupted empty-id item.

By contrast, `create()` always generates a UUID, so this only affects the NDJSON-restore path.

**Fix:** In `from_dict`, raise `ValueError` (or substitute a freshly generated UUID) if `id` is empty/whitespace. Similarly validate `ts` format.

**Files:** `KrabEar/backend/models.py` lines 154–156

### F5 MED — PII fields lack any annotation or serialisation exclusion mechanism

`chat_id` and `message_id` store Telegram chat/message identifiers. Combined with `text` (transcript content), `source_text`, `translated_text`, `audio_path`, `word_timestamps`, and `speaker_turns`, these constitute PII data. None of these fields are annotated as PII (no metadata, no `PRIVACY_FIELDS` constant, no `__pii_fields__` class attribute).

As a result:
- `text_anonymizer.py` anonymises transcript text only if explicitly called by the pipeline; there is no model-level hook.
- Sentry breadcrumbs (`observability.py`) correctly avoid logging `text`, but do so via ad-hoc field exclusion in the caller, not enforced at the model level.
- When privacy_mode items are exported (SRT, Obsidian sync, email digest), the model has no way to flag fields that must be redacted.

**Fix:** Add a class-level `PII_FIELDS: frozenset[str]` constant listing at minimum `{"text", "source_text", "translated_text", "cleaned_text", "chat_id", "message_id", "audio_path", "word_timestamps", "speaker_turns", "reasoning", "action_items", "decisions", "questions"}`. Consumers can check `HistoryItem.PII_FIELDS` to decide what to redact.

**Files:** `KrabEar/backend/models.py`

### F6 LOW — test_models.py coverage is narrow (only LLM fields tested)

`KrabEar/tests/test_models.py` (82 LOC, 5 test methods) covers only the D.10a LLM fields (`cleaned_text`, `llm_applied`, `llm_latency_ms`) added in a single PR. The model has grown to 26 fields including diarization, word_timestamps, speaker_turns, emotion, reasoning, action_items, and privacy_mode, none of which have dedicated model-level tests. The separate `test_history_item_forward_compat_W1238.py` tests the `_extra` sidecar which doesn't exist (see F1).

**Impact:** New fields added to `HistoryItem` have no model-level regression guard. A rebase that accidentally drops a `from_dict` branch (as happened with `TextProcessingService` import in W173) would not be caught by `test_models.py`.

**Fix:** Extend `test_models.py` with: (a) round-trip test for all 26 fields, (b) backward-compat test for each nullable field missing from a legacy payload, (c) `create()` → `to_dict()` → `from_dict()` lossless round-trip test.

**Files:** `KrabEar/tests/test_models.py`

### F7 LOW — @dataclass(slots=True) blocks _extra sidecar without workaround

`@dataclass(slots=True)` prevents adding arbitrary attributes to instances — any attempt to set `item._extra = {}` on an instance of the current class raises `AttributeError`. This is the root reason the W1238 fix was never shipped: implementing `_extra` requires either (a) adding `_extra: dict = field(default_factory=dict)` to the slot list (cheapest fix), or (b) switching to a `__slots__ + __dict__` hybrid (more complex). Both approaches are valid; option (a) is preferred because `slots=True` provides measurable memory savings at large history sizes and should be preserved.

This finding is informational context for F1.

**Files:** `KrabEar/backend/models.py` line 15
