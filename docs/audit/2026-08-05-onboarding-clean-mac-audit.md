# Аудит пути новичка: установка Krab Ear на чистый Mac

Дата: 2026-08-05 · Контекст: оценка готовности продукта к распространению за
пределы машины владельца (нишевая аудитория — профессионалы, которым важна
конфиденциальность: терапевты, юристы, врачи, журналисты).

**Метод**: статический разбор пути установки + эмпирическая проверка двух
ключевых предпосылок на живой машине. Системные настройки владельца НЕ
менялись, отдельная учётная запись не создавалась (потребовала бы явного
разрешения) — но обе точки отказа подтверждены фактами, а не предположением.

## Итог одной строкой

Путь от «скачал DMG» до «работающая диктовка» — **11 шагов с тремя полными
тупиками для непрограммиста**. Два тупика подтверждены эмпирически. В текущем
виде продукт можно отдать разработчику, но не целевой аудитории.

## Подтверждённые тупики

### T1 — Gatekeeper блокирует запуск (подтверждено)

```
$ spctl -a -vv "Krab Ear.app"
Krab Ear.app: rejected
origin=Krab Ear Dev Local

$ codesign -dv "Krab Ear.app"
Authority=Krab Ear Dev Local
TeamIdentifier=not set
```

Приложение подписано локальным self-signed сертификатом, не нотарифицировано.
macOS откажется его открыть обычным двойным щелчком; нужен обходной путь через
System Settings → Privacy & Security → «Open Anyway» (в новых macOS ещё и с
подтверждением паролем/Touch ID).

**Тот же барьер повторяется второй раз** для `bootstrap_backend.command` —
неподписанный `.command` Gatekeeper блокирует отдельно от `.app`.

Лечится только Apple Developer Program ($99/год) + нотарификация. Обходных
путей, приемлемых для непрограммиста, нет.

### T2 — на чистом Mac нет Python нужной версии (подтверждено)

```
$ /usr/bin/python3 --version
Python 3.9.6
```

`bootstrap_backend.command` требует Python >= 3.12 (константа `MIN_PY_MINOR=12`,
строка 27). Системный macOS-Python — 3.9. При отсутствии подходящего
интерпретатора скрипт печатает инструкцию и **завершается с ошибкой**
(строки 64-70):

```
warn "  • Homebrew:  brew install python@3.12   (сам Homebrew: https://brew.sh)"
warn "  • Установщик с https://www.python.org/downloads/macos/"
fail "Python >= 3.${MIN_PY_MINOR} обязателен"
```

Для целевой аудитории «поставьте Homebrew» — конец пути. Это самый вероятный
тупик: он срабатывает практически на **каждой** чистой машине.

### T3 — Terminal как обязательный этап установки (по конструкции)

Backend ставится `.command`-скриптом, который по двойному щелчку открывает
Terminal. Даже при успешном прохождении пользователь несколько минут смотрит
в чёрное окно с выводом `pip install` (~1.3 ГБ зависимостей), а в середине
процесса скрипт **интерактивно спрашивает HuggingFace-токен** (строка 138) —
термин, ничего не значащий для терапевта.

## Полный путь новичка (11 шагов)

| # | Шаг | Риск |
|---|-----|------|
| 1 | Скачать DMG, перетащить в Applications | ок |

## Дополнительные находки

- **Ветка по умолчанию — рабочая, не релизная.** `BRANCH="${KRAB_EAR_BRANCH:-codex/krab-ear-v2}"`
  (строка 23). Любая новая установка тянет код с активной ветки разработки:
  сломанный коммит там немедленно ломает установку у всех новых пользователей.
  Для публичного распространения нужен тег/релизная ветка.
- **Расхождение docs vs реальность (незначительное).** CLAUDE.md говорит, что
  bootstrap вкладывается «DMG-сборкой»; фактически это делает
  `scripts/assemble_signed_app.sh:50` (общий ассемблер, используется и DMG-, и
  CI-сборкой). Локальный dev-бандл его не содержит — там только `AppIcon.icns`.
  На путь пользователя не влияет, но `grep` по имени DMG-скрипта вводит в
  заблуждение.
- **Хорошая новость.** Инфраструктура онбординга внутри приложения уже есть и
  не с нуля: `QuickStartWindowController` (main.swift:1433), `ModelDownloadStep`,
  `download_stt_model`/`get_stt_model_status` IPC, `repair_permissions.command`,
  startup diagnostics. Проблема не в отсутствии онбординга, а в том, что до
  него пользователь не доходит.

## Что это значит для монетизации

Продавать в текущем виде нельзя: каждая продажа непрограммисту = гарантированный
тикет поддержки ещё до первого запуска, причём на шаге T2 помочь удалённо почти
невозможно.

Порядок снятия барьеров (по соотношению «эффект / стоимость»):

1. **Убрать Python-зависимость** — упаковать интерпретатор и зависимости внутрь
   `.app`. Снимает T2 и T3 разом, не требует денег, только работы. Бандл
   вырастет до ~1.5 ГБ — для DMG приемлемо.
2. **Apple Developer Program + нотарификация** ($99/год) — снимает T1 (оба
   вхождения). Дешёво деньгами, но требует решения владельца.
3. Прибить установку к релизному тегу вместо рабочей ветки.

После 1+2 путь сокращается с 11 шагов до примерно 4: скачать → перетащить →
запустить → выдать разрешения. Это уровень, на котором продукт можно предлагать
целевой аудитории.

## Не проверено

Живая установка на физически чистой машине/учётной записи не выполнялась
(требует изменения системных настроек владельца). Все выводы выше — из
статического разбора и точечных эмпирических проверок; перед релизом такую
проверку стоит провести отдельно, она может вскрыть дополнительные шаги
(например поведение TCC при первом запросе на незнакомой машине).
