## 1. Инициализация движков (Silero + Kokoro)

### 1.1 Double-Checked Locking (DCL) — корректность

`_get_silero` (строки 153–161) и `_get_kokoro` (строки 163–171) реализуют DCL: флаг `_silero_attempted` читается **без** лока, затем перепроверяется **внутри** лока.

**Анализ:**
В CPython с GIL чтение `bool` атомарно: если поток видит `True`, инициализирующий блок (под локом) уже завершён, поэтому `self._silero` гарантированно установлен. Паттерн корректен под CPython, но технически является data race по Python Memory Model (нет `threading.Event` барьера). При гипотетическом переходе на GIL-free (Python 3.13+ без GIL) паттерн сломается.

**Находка D1 (INFO):** DCL безопасен под CPython 3.12 (текущий). Для будущей GIL-free совместимости следует заменить флаги на `threading.Event` или двойную проверку под одним локом без внешнего быстрого пути.

### 1.2 Загрузка Silero через `torch.hub.load` — сетевая зависимость

`_load_silero` (строка 56) вызывает `torch.hub.load("snakers4/silero-models", ...)` — при первом запуске скачивает zip с GitHub. Нет явного timeout.

**Находка D2 (MEDIUM):** `torch.hub.load` при cold start (нет кэша) может висеть неограниченно при медленном/нестабильном сетевом соединении. Функция оборачивает весь вызов в `except Exception → None`, поэтому повисший поток заблокирует `_silero_lock` и все вызовы `_get_silero()` — включая основной IPC-обработчик — заморозятся до разрешения или timeout сети. Нет `timeout` аргумента в `torch.hub.load` API.

**Рекомендация:** Запускать `_load_silero` / `_load_kokoro` в отдельном `threading.Thread` с `daemon=True` и задавать таймаут через `thread.join(timeout=30)`. При превышении — сразу писать `self._silero = None` + `self._silero_attempted = True`, не ждать.

### 1.3 Отсутствие перезагрузки моделей

После неудачной загрузки (`_silero_attempted = True`, `_silero = None`) движок навсегда помечен как недоступный в рамках процесса. Нет IPC-метода `reload_tts_models` или retry-триггера через `set_settings`.

**Находка D3 (LOW):** Если torch не был установлен при первом старте и пользователь установил его позже, восстановить Silero без перезапуска бэкенда невозможно. Для production это некритично, но вводит в заблуждение при диагностике.

## 2. Точность языко-детекции (`_detect_language`)

### 2.1 Испанский язык — системный gap

`_detect_language` возвращает только `"ru"` или `"en"`. Испанский текст (латиница, нет кириллицы) → `"en"`. Затем Kokoro пытается синтезировать его с `lang_code="en-us"`.

**Находка D4 (MEDIUM):** Kokoro-82M поддерживает только английский (American/British English phoneme set). Испанский текст через Kokoro производит фонетически искажённый вывод — слова читаются по-английски. Никакого предупреждения в логах нет. При `TTS_ENABLED=False` проблема скрыта (macOS `say` адаптируется к языку автоматически через системную локаль).

Krab Ear позиционируется как **RU/ES primary** продукт (см. CLAUDE.md). Испанский TTS является ожидаемым use-case.

**Рекомендация:** Расширить `_detect_language` детекцией испанских диакритиков (`á`, `é`, `í`, `ó`, `ú`, `ñ`, `¿`, `¡`) + испанских стоп-слов. При `lang="es"` → fallback сразу на `_say_to_wav` с `voice="Monica"` (испаноязычный голос macOS) пока Kokoro ES недоступен.

### 2.2 Кириллица не-русских языков

Диапазон U+0400–U+04FF включает болгарский, украинский, сербский, македонский. Они будут направлены в Silero RU-модель.

**Находка D5 (INFO):** Ожидаемое поведение для current scope (RU primary), но не задокументировано. Украинский текст (`є`, `і`, `ї`, `ґ`) детектируется как русский и синтезируется с русским акцентом через Silero. Не является регрессией, но стоит упомянуть при работе над UA-локализацией.

### 2.3 Текст без алфавитных символов

Строки из цифр, пунктуации, URL (`"https://..."`, `"+7 495 123 45 67"`) → `alpha_chars = []` → `"en"` → Kokoro. macOS `say` справляется с цифрами значительно лучше (произносит как числа), тогда как Kokoro произносит каждую цифру по буквам.

**Находка D6 (LOW):** Отдельного числового пути нет. Низкоприоритетное UI-качество, не блокирует production.

## 3. Буферизация аудио-вывода и очистка

### 3.1 Silero: `io.BytesIO` — корректно

`_synthesize_silero` пишет результат в `io.BytesIO`, извлекает `buf.getvalue()`, буфер автоматически собирается GC. Никаких temp-файлов. Никаких утечек. Корректно.

### 3.2 Kokoro: итеративная конкатенация

`_synthesize_kokoro` аккумулирует `all_samples: list[Any]` в памяти, затем `np.concatenate`. Для длинных текстов pipeline генерирует много чанков, каждый из которых живёт в памяти до конкатенации.

**Находка D7 (LOW):** Нет streaming-записи в WAV: все чанки держатся в RAM до финального `np.concatenate`. Для типичных TTS-текстов (<500 символов) несущественно. При синтезе длинных документов возможен пик RAM до ~100 МБ (24000 Hz × 32-bit float × длительность). Альтернатива: инкрементальная запись в `wave.open` stream.

Также: `sample_rate = 24000` хардкодирован (строка 216). Если Kokoro обновится и изменит частоту, WAV-заголовок будет некорректным.

**Находка D8 (LOW):** `sample_rate` Kokoro не читается из pipeline-объекта — хардкод 24000 Hz без динамической проверки.

### 3.3 `_say_to_wav`: temp-файлы

`_say_to_wav` создаёт два `NamedTemporaryFile(delete=False)`:
- `aiff_path` — AIFF выход `say`
- `wav_path` — WAV результат `afconvert`

Оба удаляются в блоке `finally` (строки 126–130).

**Корректно:** `finally` гарантирует удаление даже при исключении. `os.unlink` с `except OSError: pass` обрабатывает race condition.

**Находка D9 (MEDIUM):** `os` импортируется **дважды внутри функции** — `import os as _os` на строке 120 (внутри `try`) и строке 126 (внутри `finally`). Это лишний round-trip к системному модульному кэшу при каждом вызове `_say_to_wav`. Следует импортировать `os` на уровне модуля (уже импортированы `re`, `subprocess`, `tempfile`, `threading`, `wave` — добавить `os`).

## 4. Покрытие логами ошибок

### 4.1 Провал `say` — тихий

Если `say` завершается с ненулевым exit code (например, текст пустой после strip, недопустимые символы, слишком длинный текст), код продолжает выполнение и запускает `afconvert` на пустом/отсутствующем AIFF. `afconvert` тоже тихо падает. Итог: `_say_to_wav` возвращает `b""`, никакого WARNING в логах.

**Находка D10 (MEDIUM):** Нет явной проверки успешности `say` с logging. Предложенный fix:

```python
result_say = subprocess.run(cmd_say, check=False, capture_output=True)
if result_say.returncode != 0 or not _os.path.getsize(aiff_path):
    logger.warning(
        "macOS say завершился с ошибкой: code=%d stderr=%s",
        result_say.returncode,
        result_say.stderr.decode(errors="replace")[:200],
    )
    return b""
```

### 4.2 Провал `afconvert` — тихий

Аналогично: `afconvert` запускается с `check=False`. Если конвертация не удалась, `wav_path` может быть пустым или отсутствовать — обрабатывается проверкой `getsize > 0`. Нет WARNING.

**Находка D11 (LOW):** Добавить аналогичный WARNING после `afconvert`.

### 4.3 Покрытие логами ML-движков

- `_load_silero`: ImportError → `DEBUG`, прочее → `WARNING`. Корректно.
- `_load_kokoro`: аналогично. Корректно.
- `_synthesize_silero`: `except Exception` → `WARNING`. Корректно.
- `_synthesize_kokoro`: `except Exception` → `WARNING`. Корректно.
- `synthesize_speech`: переходы fallback логируются на `DEBUG`. Корректно, не шумит в production.

Общая оценка логов ML-пути: хорошая. Проблема только в `say`/`afconvert` пути.

## 5. IPC handler — точность поля `engine`

`handle_synthesize_speech` определяет поле `engine` **после** синтеза по наличию загруженной модели (`self._silero is not None`), а не по фактически использованному движку (строки 333–340).

**Сценарий:** Silero загружен (`_silero is not None`), но `_synthesize_silero` выбросил исключение и вернул `None`, синтез пошёл через `say`. `handle_synthesize_speech` вернёт `engine="silero"` — некорректно.

**Находка D12 (LOW):** Это повторение D8 из Wave 839 (F-8), но с дополнительным разбором конкретного сценария-триггера. Рекомендованный fix из W839 остаётся актуальным: `synthesize_speech` должен возвращать `(bytes, engine: str)` tuple.

## 6. Безопасность

**Инъекция через `voice`:** строка 108 санитизирует голос regex `^[a-zA-Z0-9 _\-]+$`. Fallback `"Milena"`. `subprocess.run` с `list` (не `shell=True`) — безопасно.

**Инъекция через `text`:** текст передаётся как отдельный аргумент в `subprocess.run` list — без shell-интерпретации. Безопасно.

**Путь к temp-файлам:** `tempfile.NamedTemporaryFile` создаёт файлы в системном temp-dir с уникальными именами — нет path traversal.

**Вывод:** нет security-находок. Поверхность атаки минимальна.

## 9. Приоритеты исправления

1. **D10 / D11** — добавить WARNING при провале `say`/`afconvert`. Однострочный fix, высокая диагностическая ценность.
2. **D9** — вынести `import os` на уровень модуля. Тривиальный рефактор.
3. **D4** — ES language detection. Требует расширения `_detect_language` + выбора ES-голоса macOS say. Средняя трудоёмкость, высокая ценность для RU/ES use-case.
4. **D2** — timeout для `torch.hub.load`. Требует оборачивания в thread + join с таймаутом. Средняя трудоёмкость, предотвращает IPC freeze при сетевых проблемах.
5. **D12** — `(bytes, engine)` tuple из `synthesize_speech`. Небольшой рефактор IPC handler.
