## Summary

6 findings: 1 HIGH, 2 MEDIUM, 3 LOW.

The core EventBus design (queue-per-subscriber, lock only for list mutation, lock released before dispatch) is
sound. The known lock-order hazard (error_bus._lock → event_bus.emit → SSE callback) is documented and
mitigated at the call site (recorder.py W1652 F3). No new lock-inversion bugs found.

## Findings

### F1 HIGH — `bus._event_replay` is never wired; replay integration is dead code

**Location:** `backend/event_bus.py:42`, `backend/service.py:468`

The `EventBus.__init__` declares `self._event_replay: Any | None = None` as a "late-injected"
field. The docstring says "set after both objects are constructed", yet no production path ever
assigns `event_bus._event_replay = ...`. `BackendService.__init__` creates a local
`self._event_replay = EventReplayManager(...)` but never injects it into the global `bus` singleton:

```python
# service.py:468 — local only, never pushed into the bus
self._event_replay = EventReplayManager(persist_path=...)
```

`grep -rn 'bus._event_replay\s*='` returns zero matches in all non-test files. As a result every
`emit()` call silently short-circuits the replay path:

```python
if self._event_replay is not None:   # always False in production
    ...
```

The `EventReplayManager` never receives events through the bus; `get_event_log` / `get_event_stats`
/ `replay_events` IPC handlers exist but their ring buffer is always empty.

**Fix:** In `BackendService.__init__` after constructing both objects, add:

```python
event_bus._event_replay = self._event_replay
```

This is a one-liner that closes the wiring gap without any schema change.

### F2 MEDIUM — Transcript text emitted in SSE events with no privacy-mode gate

**Location:** `backend/recording_core_service.py:1262-1280`

`STT_FINAL` (`stt.final`) and `realtime.final_transcript` events carry full transcript text:

```python
event_bus.emit_typed(EventType.STT_FINAL, SttFinal(
    history_id=item.id,
    text=final_text,           # full transcript text in SSE payload
    ...
))
event_bus.emit("realtime.final_transcript", {"text": final_text, ...})
```

`STT_PARTIAL` / `live_subs.result` also send text. There is **no check for
`privacy_mode_enabled` before these emits**. The REST `/events` SSE endpoint
(`rest_server.py:1170`) is gated by `require_api_key`, but:

1. Local attackers or rogue extensions connecting to localhost:5005 receive full transcript text
   via SSE/WebSocket if the API token is weak or absent (default dev mode has no auth).
2. The `event_replay.ndjson` file (once F1 is fixed) will persist transcript text to disk
   regardless of privacy mode.

The pattern used elsewhere in the codebase (session_tracker, auto-dedup, calendar-link) is to
check `privacy_mode_enabled` and either skip the action or redact sensitive fields.

**Fix:** Wrap `STT_FINAL` / `STT_PARTIAL` / `realtime.final_transcript` emits with a
`privacy_mode_enabled` guard and either suppress the text field (replace with an empty string or
omit) or skip the emit entirely when privacy mode is active.

### F3 MEDIUM — No shutdown sentinel delivered to active SSE/WS subscribers

**Location:** `backend/event_bus.py:44-54`, `backend/shutdown_handler.py`

`sse_stream` and `_handle_ws_connection` both block on `q.get(timeout=...)` in a loop and
exit when they receive `None`. The docstring for `subscribe()` states "None в очереди означает
сигнал завершения". However, `GracefulShutdownHandler` (`shutdown_handler.py`) does not walk
`bus._subscribers` and inject `None` sentinels on shutdown. Neither does any other shutdown
path.

Effect: on clean backend shutdown, live SSE clients (e.g. `LiveSubtitlesOverlay.swift` polling
`/events`) stay blocked for up to `_SSE_POLL_TIMEOUT_SEC` (15 s) before noticing the server is
gone. During that window the subscriber queue remains allocated in the bus's `_subscribers`
list, and the HTTP response generator thread is alive but blocked — a 15 s hard delay before
the client connection closes.

**Fix:** Add a `shutdown()` method to `EventBus` that iterates `_subscribers` under lock,
puts `None` into each queue, and clears the list. Call it from
`GracefulShutdownHandler._shutdown_backend()` after other services are stopped.

### F4 LOW — `_event_replay.record_event` called with the raw payload dict, not the envelope

**Location:** `backend/event_bus.py:88`

```python
self._event_replay.record_event(event_type, payload)
```

The `event` dict assembled at line 70 includes `{"type", "ts", "data"}` (the EVENT_CONTRACT_V1
envelope). But `record_event` receives only `event_type` (str) and `payload` (the inner `data`
dict). The `ts` field computed by `emit()` is discarded; `EventReplayManager.record_event` must
generate its own timestamp. If the two timestamps ever diverge (e.g. clock jitter between the
two calls), replayed events will have a different `ts` than the one delivered to subscribers.

This is a latent correctness issue that will surface once F1 is fixed and the replay path
becomes active.

**Fix:** Pass the full envelope dict to `record_event`, or change the call signature to
accept the already-computed `ts`.

### F5 LOW — `sse_stream` event filter uses comma-split but no validation; malformed filter silently passes all events

**Location:** `backend/event_bus.py:112-114`

```python
allowed = {t.strip() for t in event_filter.split(",") if t.strip()}
```

An empty filter string (`?filter=`) produces `allowed = set()` (empty set). The subsequent
guard at line 130:

```python
if allowed is not None and event["type"] not in allowed:
    continue
```

…skips delivery for every event type when `allowed` is empty, so the client receives nothing but
keepalives. This is likely not the intended behavior for `?filter=` (caller probably expects all
events). `None` vs empty-set semantics differ, and the distinction is not documented.

Additionally, there is no input sanitization on `event_filter` before it reaches the set
comprehension. A very long filter string (>1 KB) is accepted without truncation — a minor DoS
vector via the REST API.

**Fix:** Treat empty `allowed` set as "no filter" (pass-through), or document and test the
empty-filter behavior explicitly. Add a length cap on `event_filter` in the REST endpoint.

### F6 LOW — Module-level `bus` singleton shared between IPC service and REST server; no isolation for tests

**Location:** `backend/event_bus.py:139`, `backend/service.py:75`, `backend/rest_server.py:30`

Both `service.py` and `rest_server.py` import the same module-level `bus` singleton:

```python
from backend.event_bus import bus as event_bus
```

This means events emitted by the IPC service are automatically delivered to any REST SSE
subscriber and vice versa — which is intentional for normal operation. However, it creates a
**test isolation hazard**: any test that imports `backend.service` or `backend.rest_server`
will share the same `bus` object. A subscriber registered in one test file and not cleaned up
leaks into subsequent tests (subscriber_count accumulates). The existing tests use `EventBus()`
instances directly which avoids this, but test fixtures that patch `backend.event_bus.bus` via
`MagicMock()` (e.g. `test_rest_no_duplicate_gigaam.py:136`) may interfere if the module is
already imported.

**Fix:** Add a `bus.reset()` method (empties `_subscribers`, clears `_event_replay`) and call
it in test teardown when using the singleton. Alternatively, provide a test-scoped factory
function `make_bus()` to replace direct singleton access in the two server modules.

## Lock-safety verdict (re-confirmed)

The lock is held **only** during `_subscribers` list mutation (`subscribe` / `unsubscribe`) and
snapshot copy (`emit`). Callbacks (queue puts) and `_event_replay.record_event` run outside the
lock. This pattern correctly prevents the W1649 F3 deadlock class. No new lock issues found.
The known hazard (`error_bus._lock → event_bus.emit → SSE callback → recorder.is_recording`)
is correctly handled in `recorder.py` (W1652).
