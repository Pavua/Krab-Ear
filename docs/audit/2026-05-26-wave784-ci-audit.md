# Wave 784 CI Audit — krabear-ci.yml gaps & improvements

**Date**: 2026-05-26  
**Branch**: feature/ci-workflow-audit-W784  
**Auditor**: Wave 784 sub-agent

## Scope

Compared `.github/workflows/krabear-ci.yml` (the branch-agnostic CI that runs on every push)
against `.github/workflows/ci.yml` (the main-branch CI) to identify gates present in one
but absent in the other, then classified each gap as ADDED or REPORT-ONLY.

---

## Gaps identified: 8

### ADDED (4 steps / jobs added to krabear-ci.yml)

| # | Gap | Action | Rationale |
|---|-----|--------|-----------|
| 1 | **No flake8 lint** | Added `Lint (flake8)` step | `ci.yml` runs flake8 with identical config; `krabear-ci.yml` (the always-on workflow) was silently skipping lint on every branch push. Matching config: `--max-line-length=150`, test file ignores `F401,F541,F841,E203,E303,E306,E401,E402,W391`. |
| 2 | **No test coverage report** | Added `--cov=KrabEar --cov-report=term-missing` to pytest invocation | `ci.yml` generates a coverage summary; `krabear-ci.yml` did not. Visible in CI log without uploading an artifact. |
| 3 | **No `verify-claude-md` job** | Added `verify-claude-md` job (mirrors `ci.yml`) | CLAUDE.md drift can occur on any branch, not just `codex/krab-ear-v2`. The drift-check script (`scripts/verify_claude_md.py`) is lightweight (stdlib only, no pip install needed). |
| 4 | **Python 3.11 vs 3.12 mismatch** | Bumped to `python-version: "3.12"` | `ci.yml` tests on 3.12; `krabear-ci.yml` tested on 3.11. Running different Python versions in the two workflows hides version-specific breakage. Cache keys updated accordingly. |

### REPORT-ONLY (marginal gaps — not added)

| # | Gap | Verdict | Rationale |
|---|-----|---------|-----------|
| 5 | **Black / isort code style** | Not added | No black/isort config exists in the repo; adding an enforcement step before the tool is configured would break all PRs immediately. Recommended as a follow-up: add `pyproject.toml` with `[tool.black]` then wire to CI. |
| 6 | **mypy type check** | Not added | No `mypy.ini` / `py.typed` markers in the codebase. The heavy optional-dep footprint (mlx, pyannote, sounddevice, torch) makes a clean mypy run non-trivial without stub packages. Worth a dedicated wave. |
| 7 | **`test_dispatch_invariants_*` explicit gate** | Not needed | Three invariant test files (`test_dispatch_invariants_wave654.py`, `test_dispatch_invariants_wave693.py`, `test_ipc_dispatch_invariants.py`) are already collected by the catch-all `python -m pytest KrabEar/tests/ ...` invocation. No separate step required. |
| 8 | **GitGuardian secret scan** | Not added | GitGuardian is a third-party SaaS integration (requires org-level setup / API token secret in repo settings). Not something to wire unilaterally in a CI audit wave; tracked in `docs/audit/2026-05-26-wave663-gitguardian.md`. |

## Changes made

File: `.github/workflows/krabear-ci.yml`

1. Python bumped `3.11 → 3.12` (setup-python + pip cache key).
2. `pip install` extended: added `pytest-cov flake8`.
3. New step **`Lint (flake8)`** inserted before `Run backend/unit tests`.
4. `Run backend/unit tests` step: added `timeout-minutes: 25` + `--cov=KrabEar --cov-report=term-missing`.
5. New job **`verify-claude-md`** added after `swift-build` (mirrors `ci.yml`).

YAML validated: `python3 -c "import yaml; yaml.safe_load(...)"` → ok.
