## F1 — HIGH: `handle_add_abbreviation` duplicate STILL present in `text_processing_service.py`

**File:** `KrabEar/backend/text_processing_service.py`  
**Lines:** 297–323 (first def) and 353–372 (shadow def)  
**Severity:** HIGH  

The W1442 PR claimed to fix this duplicate but the shadow is still present in the codebase (confirmed by live run of `audit_duplicate_defs.py`). Python uses the **last** definition at class-load time, so line 353's `handle_add_abbreviation` (using `"abbr"` param key) completely shadows line 297's version (using `"abbreviation"` param key).

**Impact:** Callers passing `{"abbreviation": ..., "expansion": ...}` silently get an empty `abbr=""` string because the active handler reads `params.get("abbr", "")`. The parameter validation check `if not abbr` then raises `ValueError: abbr и expansion обязательны`, returning a 5xx IPC error instead of adding the abbreviation.

**Test exposure:** `TestAbbreviationHandlers.test_add_abbreviation_dispatched` (line 360) and related tests at lines 374/390/398/404 pass `"abbreviation"` key — these tests **pass by accident** today only if those test methods invoke the *first* def before Python has finished loading the class body. In production the shadow is always active.

**Fix:** Remove the duplicate at line 353–372, and merge its `"abbr"` param reading into the surviving handler at line 297 (accept both `params.get("abbreviation") or params.get("abbr")`).

## F2 — HIGH: `_escape_as_str` duplicate STILL present in `service.py`

**File:** `KrabEar/backend/service.py`  
**Lines:** 3133–3141 (first def) and 3239–3247 (shadow def)  
**Severity:** HIGH  

Same pattern. The shadow at line 3239 is the **better** implementation (strips `\r\n\x00` control characters, double-escapes backslash-before-quote — the W1028-F5 / W944 security fix). The first def at line 3133 is the naive version that does NOT strip control chars and is vulnerable to AppleScript injection via `\r`/`\n` in user-supplied text.

**Impact:** All Apple Notes / Reminders / Calendar / iMessage integrations that call `self._escape_as_str()` before building AppleScript strings use the **correct** (second) implementation since Python shadows with the last def. However the dead first def is misleading and could be accidentally restored in a future cherry-pick, re-introducing the injection vulnerability silently.

**Fix:** Remove the first def at line 3133–3141 (keep only the safer version at 3239).

## F4 — LOW: `waveform_generator.py` `rms_amplitude` unguarded on single-element arrays

**File:** `KrabEar/core/waveform_generator.py`, line 77  
**Severity:** LOW  

```python
rms_amplitude = float(np.sqrt(np.mean(np.square(data, dtype=np.float64))))
```

There is no guard against `data` being all-zero or all-NaN (e.g. corrupt audio). `np.mean` on all-NaN returns `nan`, and `np.sqrt(nan) = nan`, which propagates to the IPC response dict. `AudioAnalyticsService.handle_get_waveform` (line 167) returns `rms_amplitude: wf.rms_amplitude` directly, so a NaN would end up in the JSON-serialized IPC response and break `json.dumps` (raises `ValueError: Out of range float values are not JSON serializable`).

**Contrast with `audio_quality.py`:** The W1442 `_safe_float` fix guards `rms_level`, `peak_level`, etc. with `float(x)` + ternary `if n_samples > 0 else 0.0`. The waveform generator has the empty-array fast path (line 66–73) but no NaN guard for non-empty corrupt data.

**Fix:** Wrap with `math.isfinite` check or clamp: `rms_amplitude = float(x) if math.isfinite(x) else 0.0`.

## F5 — LOW: `handle_add_abbreviation` response API is inconsistent — dual-key workaround needed

**Files:** `KrabEar/backend/text_processing_service.py`, `KrabEar/tests/test_text_processing_service.py`  
**Severity:** LOW  

The W1442 PR description says it "restored the `abbreviation` key for dual-key compat". However the current active handler (shadow, line 353) returns `{"added": True, "abbr": ..., "language": ...}` — it does NOT include an `"abbreviation"` key in the response. Tests at line 370 (`self.assertEqual(result["abbreviation"], "т.н.")`) therefore target the DEAD first handler.

Swift callers: `grep -r "add_abbreviation" native/` returns no results — there is no Swift caller for this IPC method yet. The IPC_API_REFERENCE documents the response as `{added, abbreviation, expansion, language}` (first def's contract), but the live runtime returns `{added, abbr, language}` (shadow def's contract). Any future Swift caller that follows the documented contract will silently get a `nil` abbreviation value.

**Fix:** The surviving handler must return both `"abbreviation"` and `"abbr"` keys (or the IPC reference must be updated to match the `abbr`-only contract).

## Performance verification: `_safe_float` O(1) — no hot-loop concern

`audio_quality.analyze()` calls `_safe_float` (the `float(x)` wrapping pattern) exactly 5 times: `rms_level`, `peak_level`, `clipping_ratio`, `silence_ratio`, `snr_estimate_db`. Each is a single scalar float cast — O(1) per call, negligible cost. The hot loop is `_compute_silence_ratio()` which iterates frames internally but does not call `_safe_float`. No performance regression.
