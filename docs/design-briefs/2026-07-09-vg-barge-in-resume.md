# VG-бриф: barge-in resume-on-false-positive (Волна 3c Krab Ear)

Дата: 2026-07-09. Для параллельной сессии в репо `/Users/pablito/Antigravity_AGENTS/Krab Voice Gateway`.
Контекст-сиблинг: Волна 3b (brain_mode, VG PR #64) — тот же кросс-репо паттерн.

## Проблема

`app/conversation/ws_handler.py::_handle_pipeline_utterance`, playback-цикл (~строки 576-592):
на КАЖДЫЙ TTS-чанк вызывается `_drain_for_speech()`; любое срабатывание (VAD поймал «речь») →
немедленно `ConvEventType.INTERRUPTED` + `return carried` → остаток TTS-фреймов ответа
**потерян навсегда**. `_is_speech` — энергетический VAD: кашель, стук, громкий фон проходят порог.
Итог: ложное срабатывание = ответ ассистента оборван без возможности продолжить.

Владелец Krab Ear хочет поведение «как человек»: осмысленная речь перебивает; кашель/шум — нет;
если сработали ложно — продолжить ответ с места паузы (короткая заминка допустима).

## Требуемое изменение (playback-фаза)

При срабатывании `_drain_for_speech()` в **playback**-цикле:
1. НЕ слать `INTERRUPTED` сразу. Прогнать захваченный `carried`-фрагмент через быстрый ASR
   (у engine уже есть ASR-путь — `run_pipeline_turn` его использует; нужен лёгкий вызов только-ASR,
   без brain/TTS).
2. Распознан осмысленный текст (непустой после strip; на ваше усмотрение — минимальная длина,
   например ≥2 символов, чтобы отсечь «а», «эм») → текущее поведение: `INTERRUPTED` + вернуть
   carried-аудио в следующую реплику. Желательно НЕ терять уже сделанную ASR-работу (не гонять
   ASR второй раз в следующем ходе), но это внутренняя оптимизация — решайте сами.
3. Пусто/шум → **проглотить**: не слать событий, продолжить досылку оставшихся TTS-фреймов с
   места паузы. Клиент ничего не заметит, кроме заминки на время ASR.

Пока ASR-проверка идёт, досылку фреймов приостановить (не слать параллельно с проверкой — иначе
при подтверждённом прерывании юзер услышит лишний хвост).

## Контракт с клиентом — НЕ меняется

`conv.interrupted` теперь означает «подтверждённая речь» — клиент Krab Ear строит на этом свою
обработку (останавливает локальный плеер, состояние → listening). Никаких новых событий/полей.
Проглоченное ложное срабатывание для клиента невидимо (downlink-фреймы просто продолжаются).

## Опционально (НЕ обязательство, если дёшево — тем же паттерном)

Compute-фаза (~строки 516-545) имеет ту же проблему: barge во время «думания» отменяет
`turn_task` — кашель роняет ответ ещё до того, как он прозвучал. Тот же ASR-confirm паттерн
применим: не отменять turn_task до подтверждения осмысленности (turn продолжает считаться, пока
ASR проверяет — потерь латентности у реального прерывания нет, у ложного — ответ спасён).
Если раздувает скоуп — пропустить, зафиксировать TODO.

## Гейты

- Unit-тесты: ложный barge (шумовой фрагмент, ASR→пусто) → фреймы досланы полностью, событий нет;
  реальный barge (ASR→текст) → `INTERRUPTED` + остаток не дослан; порядок контрольных фреймов
  из `_drain_for_speech` сохранён (там уже есть логика rest→put_nowait — не сломать).
- Латентность заминки залогировать (INFO) — понадобится при живом смоке для калибровки.
- После мержа: живой кросс-репо e2e с Krab Ear-стороной (план у Krab Ear-сессии; урок 3b — только
  живой тест между реальными процессами ловит стыковые гэпы).
