# Бриф для Main Krab: голосовой режим ответов через OpenClaw operator API

Контекст: голосовой ассистент Krab Ear («Разговор с AI», через Voice Gateway) переводит
Main Krab из режима «последний фоллбэк» в режим «основной мозг разговора» (по выбору
владельца, тоггл в UI). Voice Gateway зовёт Main Krab через OpenClaw operator API
(`x-openclaw-scopes: operator.write,operator.read`) — это тот же канал, что уже
используется, просто теперь он в приоритете, а не в хвосте.

Это ЖИВОЙ голосовой разговор: ответ Main Krab синтезируется в речь (TTS) и проигрывается
пользователю вслух. Значит ответ должен быть коротким, естественным разговорным текстом —
БЕЗ markdown, списков, эмодзи, длинных пояснений.

## Известная проблема (задокументирована в коммите VG `ac330a2`)
При понижении приоритета openclaw в VG была явно указана причина: канал «игнорит
system-prompt» — то есть Main Krab, судя по всему, использует свою собственную
зашитую персону/инструкции независимо от того, что приходит в `messages` от вызывающей
стороны.

## Просьба
1. **Подтвердите/проверьте**: когда VG зовёт operator API с `messages`, где есть
   system-роль с просьбой отвечать кратко и в разговорном стиле — Main Krab реально это
   учитывает, или у агента есть свой фиксированный system-prompt, который побеждает?
2. Если игнорирует — нужен ЛЮБОЙ рабочий способ сообщить «это голосовой режим, отвечай
   коротко и естественно» так, чтобы агент это реально учёл (заголовок, параметр,
   специальный формат сообщения — на ваше усмотрение, не обязательно глубокая архитектурная
   правка, возможно достаточно флага в слое построения промпта).
3. **Отдельно подтвердите**: вызов через operator-scope даёт Main Krab доступ к обычной
   памяти/контексту/MCP-инструментам (то, ради чего вообще имеет смысл звать именно Krab, а
   не generic LLM), или operator-режим работает более изолированно/statelessly? Это влияет
   на то, есть ли вообще смысл в этой интеграции — стоит подтвердить прежде, чем считать
   фичу готовой.
4. Скорость ответа — не горит с вашей стороны: у VG настраиваемый generous timeout (дефолт
   30с для явного режима «Krab», короче для авто-режима с фоллбэком) — блокировать вас никто
   не будет, важнее стиль ответа и подтверждение доступа к памяти/контексту, а не скорость.

Это часть кросс-проектной фичи: Krab Ear (UI разговора) → Voice Gateway (транспорт/оркестрация,
параллельный бриф уже ушёл в ту сессию) → Main Krab (собственно мозг, через OpenClaw). Если
нужны уточнения — спрашивайте через владельца, он на связи с обеими сессиями.
