# Autonomous Execution Plan (Krab Ear)

Дата версии: 2026-02-12  
Статус: Active

## 1. Цель

Сделать длинные автономные сессии разработки и верификации предсказуемыми:

1. Агент работает сериями спринтов без ручного микроменеджмента.
2. После каждой серии есть проверяемый артефакт (код + отчёты + обновлённые docs).
3. Core-функция (`hotkey -> запись -> STT -> вставка -> история`) не деградирует.

## 2. Режимы автономной работы

1. `Короткий` (20-40 минут): 1 небольшая фича или точечный фикс.
2. `Средний` (60-120 минут): фича + стабилизация + документация.
3. `Длинный` (2-4 часа): mini-release цикл (несколько спринтов + полный прогон).

## 3. Контракт на один автономный цикл

Каждый цикл обязан закончиться:

1. Зелёной сборкой `swift build -c release`.
2. Зелёными unit-тестами Python.
3. Прогоном `Run Release Smoke.command`.
4. Новым отчётом в `docs/reports`.
5. Обновлёнными `README/ROADMAP` при изменении поведения.

## 4. Что делает агент, если roadmap закончился

Если активная очередь спринтов закрыта:

1. Агент не останавливается мгновенно.
2. Агент берёт low-risk улучшения из техдолга и стабильности.
3. Агент формирует блок `PROPOSAL` в `ROADMAP.md` для high-risk изменений.
4. Агент не внедряет high-risk изменения молча.

Правило:
- low-risk правки может выполнять автономно;
- high-risk изменения требуют явного подтверждения пользователя.

## 5. Как запрашивать 60-минутную автономную сессию

Рекомендуемый формат команды пользователю агенту:

1. Время: `60 минут`.
2. Приоритет: например `Sprint S07`.
3. Ограничения: `не ломать core flow`, `offline-first`.
4. Формат отчёта: `сделано/проверено/остаток/риски`.

Пример:
`Работай автономно 60 минут по Roadmap (S07): реализуй RU->ES и ES->RU режимы перевода, сам тестируй, в конце дай отчёт и чек-лист ручной проверки.`

## 6. Разница между “автономная разработка” и “автономные тесты”

Команда:
`/Users/pablito/Antigravity_AGENTS/Krab Ear/Run Autonomous Cycle.command`

Это в первую очередь:
1. build;
2. unit tests;
3. smoke;
4. soak;
5. отчёт.

Это полезно как quality-gate, но не заменяет постановку продуктовых задач агенту в чате.

## 7. Sprint-шаблон (для любой модели)

1. `Sx.1`: функционал (код + минимальные тесты).
2. `Sx.2`: стабильность (рефактор + edge cases).
3. `Sx.3`: UX/документация (доступность фичи без терминала).
4. Gate: `build + tests + smoke (+ soak при необходимости)`.

## 8. Definition of Done для “стабильного этапа”

1. `crash_count = 0` в soak-отчёте.
2. smoke-check `OK`.
3. unit-tests `OK`.
4. есть стабильный backup через `Create Stable Backup.command`.
5. обновлены `README`, `ROADMAP`, `AUTONOMOUS_EXECUTION_PLAN`.

## 9. Формат финального отчёта после автономной сессии

1. Выполненные пункты спринта.
2. Список изменённых файлов.
3. Что проверено и чем.
4. Открытые риски и блокеры.
5. Следующий рекомендуемый шаг (номер следующего спринта).
