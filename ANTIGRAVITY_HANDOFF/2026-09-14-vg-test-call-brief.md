# Бриф VG-сессии: тестовый звонок через Ear call-профиль (2026-09-14)

Владелец разрешил тестовый звонок. Исполняет **VG-сессия** (там флаги,
creds, счёт и dial-механика). Ear-сессия PSTN-звонки не выполняет
(пути нет с #1990) и VG `.env`/рантайм не трогает.

## Готовность Ear (замерено 14.09, синтетика 8 кГц, без PSTN)

- `POST /v1/stt/transcribe` + `request_profile=voice_gateway_call`,
  `language=ru` → HTTP 200, текст пословно точный, `history_id=""`
  (история не пачкается), `transport=subprocess`, `engine=gigaam-rnnt`.
- 10/10 `ok`, p50 ~0.41 с, p95 ~1.36 с (тёплый воркер; первый холодный ~5.5 с).
- Busy/timeout под живой диктовкой — не замерен (оппортунистически).
- Живые флаги Ear: `privacy_mode_enabled=False` (профиль не даст 403),
  `cloud_rewriter_enabled=False`, `llm_rewrite_enabled=False`.
- Прод: релиз `6561a030` (в нём #2001), backend/REST живы.

## Просьба к VG-сессии

1. Включить **только** `KRAB_STT_EAR_CALL_PROFILE_ENABLED`
   (`KRAB_SCREENING_AUTO_LANGUAGE_ENABLED` оставить 0 — см. карточку
   `docs/superpowers/plans/2026-09-07-vg-gigaam-call-profile.md`).
2. Один короткий звонок (≤60–90 с, одна попытка, без redial-шторма).
3. Цель — **только бизнес** (отель, фронт-деск и т.п.; ночью ожидается
   админ или автоответчик). Частные/семейные номера — **запрещены**
   владельцем. Испанский стационарный предпочтителен (дешевле).
4. Замерить: латентность тёплых ходов, RU-качество, поведение
   busy/timeout, метаданные (transport/adapter/mode), стоимость звонка.
5. Приёмка: **аудиозапись звонка + транскрипт/саммари — владельцу
   в Telegram** (его требование — сможет прослушать и оценить).
   Подтвердить, что путь доставки существует, до звонка.
6. Отчёт обратно сюда: SHA VG, похардкодные латентности, качество,
   стоимость, замечания. При любой неудаче — стоп и отчёт, без повторов.

## Ограничения

- Ear-рантайм не трогать (прод-релиз, живая диктовка владельца идёт сейчас).
- Screening-флаг не включать. Cloud-rewrite не включать.
- GigaAM-MLX (экспериментальный транспорт) в этом звонке не участвует:
  call-профиль идёт через subprocess owner-воркер.
